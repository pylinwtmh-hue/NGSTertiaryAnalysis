# 三級分析 Pipeline — 評鑑大補帖

> **這份文件是什麼**
> 三級分析（VCF → 註解 → ACMG 分類 → 臨床報表）**全部原始碼的逐行註解版**。
> 每一個參數／選項的意義，寫成**行內註解**（跟在該行後面或上一行）；
> 每一個 process／workflow／函式的整體流程與設計理由，寫成**區塊註解**（放在該區塊外面、上方）。
>
> **用途**：評鑑準備時，任何一項「為什麼這樣做？」都能在這裡查到答案，
> 不用再回頭翻程式碼、翻 ACMG 指引、翻工具手冊。
>
> **範圍**：`main_tertiary.nf`、`nextflow_tertiary.config`、`modules/*.nf`、`scripts/*.py`。
>
> **注意**：本文件中的程式碼是「加了註解的原始碼副本」，**不是可執行檔**。
> 真正跑的永遠是 repo 根目錄下的檔案。改程式碼時請一併更新這裡。
>
> **姊妹文件**：二級分析的對應文件見 `NGSSecondaryAnalysis/docs/評鑑大補帖_二級分析.md`。

# 第 0 章：Pipeline 總覽

## 0.1 三級分析在做什麼

**二級分析**回答「這個人有哪些變異」；
**三級分析**回答「**這些變異有什麼臨床意義**」。

```
二級輸出（或 DRAGEN 輸出）
        │
   ┌────┴─────────────────────────────────────────┐
   │                                              │
【SNV/indel 主線】                        【其他變異類型】
   │                                              │
prepare_vcf                                 ├ CNV/SV → AnnotSV → 03/06_cnv_sv
（norm / caller tag / chrM 分流）           ├ STR   → STRchive 閾值 → 05_str
   │                                        ├ mtDNA → VEP + gnomAD-mito → 04_mito
VEP 115 註解                                └ PGx   → PharmCAT + StellarPGx + OptiType → 07_pgx
（dbNSFP / LOFTEE / ClinVar /
  Pangolin / SpliceAI / NMD …）
   │
parse_vep_csq.py
（選代表轉錄本 → 攤平成 74 欄 TSV）
   │
acmg_classifier.py
（ACMG/AMP 2015 + ClinGen SVI → 81 欄）
   │
03_acmg/<sample>.acmg.tsv  → 臨床判讀 GUI
```

## 0.2 兩條輸入路徑

| | NCKUH | DRAGEN |
|---|---|---|
| 來源 | 本院二級分析 pipeline | Illumina DRAGEN 平台 |
| SNV VCF | `04_snv_indel/*.ensemble.fixed.vcf.gz` | `vcf.gz/*.hard-filtered.vcf.gz` |
| caller 標記 | 已有 `_DV`/`_HC` 兩個樣本欄 → `add_callers_tag.py` | 單一 caller → `add_dragen_tag.py` |
| phasing/compound | **二級已做完** | **三級做**（`COMBINE_DRAGEN`，用 DRAGEN 原生 PS） |
| chrM | 二級獨立輸出 `07_mitochondria/` | 混在主 VCF 裡 → **三級要分流** |
| 倍體 QC | 二級 `ploidy_check.py` | 三級 `parse_dragen_ploidy.py`（讀原生 `ploidy.vcf`） |
| CNV | WES: gCNV VCF；WGS: CNVkit `.call.cns` | `*.cnv.vcf.gz` |
| SV | Delly `*.delly.vcf.gz` | `*.sv.vcf.gz` |
| STR | GangSTR `*.str.vcf` | `*.repeats.vcf.gz` |

**兩條路徑在 `ANNOTATE_SNV` 之後完全合流** —— VEP、CSQ 解析、ACMG 分類都是共用的。

## 0.3 貫穿全 pipeline 的四個設計原則

### 原則一：商業授權是硬約束（與二級相同）

| 工具/資料庫 | 授權 | 可商用 | 狀態 |
|------------|------|--------|------|
| VEP | Apache-2.0 | ✅ | 預設 |
| dbNSFP 4.9c | 內含工具皆可商用 | ✅ | **預設** |
| dbNSFP 5.3a | 含 CADD/REVEL 等學術免費、商用需另授權 | ⚠️ | `--academic_dbnsfp`，預設 OFF |
| LOFTEE | MIT | ✅ | 預設 |
| ClinVar | 公眾領域 | ✅ | 預設 |
| ClinGen | CC0 | ✅ | 預設 |
| gnomAD | 開放 | ✅ | 預設 |
| **gnomAD-mito v3.1** | **CC0** | ✅ | **預設（取代 MITOMAP）** |
| ~~MITOMAP~~ | CC BY-NC | ❌ | **已移除** |
| AnnotSV | GPL-3.0 | ✅ | 預設 |
| STRchive | 開放 | ✅ | 預設 |
| PharmCAT | MPL-2.0 | ✅ | 預設 |
| StellarPGx | MIT | ✅ | 預設 |
| OptiType | BSD-3 | ✅ | 預設 |
| Pangolin | 開放 | ✅ | 預設 |

> **評鑑要點**：與二級相同 —— 預設臨床路徑**完全沒有**非商用工具。
> 唯一的學術限定選項（dbNSFP 5.3a）是 opt-in flag，且 banner 會印出
> 「這次跑用的是哪一版」，可追溯。

### 原則二：ACMG 分類必須可解釋、可追溯

輸出的 81 欄 TSV 中，ACMG 相關欄位不只給結論，還給**理由**：

- `ACMG_CRITERIA` —— 觸發了哪些準則（`PVS1_Strong,PM2,PP3`）
- `ACMG_SCORE` —— 加權總分
- `PVS1_STRENGTH` / `PVS1_REASON` —— PVS1 走了決策樹的哪一條路、為什麼降級
- `CLINGEN_VCEP_CLASS` / `_CRITERIA` / `_PANEL` —— 專家小組怎麼判、用了哪些準則
- `CLINGEN_AGREEMENT` —— 我們的結論與專家判讀是否一致

判讀者不需要相信 pipeline，可以**檢查它的推理**。

### 原則三：ClinGen 專家判讀只做對照，絕不參與計分

`CLINGEN_VCEP_*` 欄位來自 ClinGen Evidence Repository（VCEP 專家小組的判讀），
但**不加分、不減分**。

**為什麼？** ACMG/AMP 的 SVI 工作小組（2018）明確建議**不要使用 PP5/BP6**
（「有信譽來源報告為致病/良性」）—— 因為那等於是把別人的結論當成自己的證據，
會造成循環論證與證據重複計算。

所以 ClinGen 判讀只出現在**對照欄位**，讓判讀者自己看「我們和專家意見一致嗎」。

### 原則四：找不到選用資料就 warn，不要讓整批失敗

臨床 pipeline 一次跑好幾個樣本。若因為「某個樣本缺一個選用檔案」就讓整批失敗，
其他樣本的結果也白跑了。所以：

- **必要資料庫**（VEP cache、dbNSFP、LOFTEE、ClinVar）→ 缺就 `error`（開跑前檢查）
- **選用資料庫**（ClinGen HI、gene MOI、ERepo）→ 缺就 `log.warn` + 降級運作
- **單一樣本的選用輸入**（mito VCF、STR VCF、DRAGEN `targeted.json`）→ 缺就 warn 後跳過該樣本的該項

# 第 1 章：`main_tertiary.nf` — 主流程

## 1.1 這個檔案負責什麼

1. **解析並驗證 sample sheet**（`parse_samplesheet`）
2. **驗證資料庫路徑**（`validate_databases`）
3. **印出執行資訊 banner**（評鑑追溯用）
4. **依 `pipeline_type` 建立各種輸入 channel**（路徑規則寫在這裡）
5. **呼叫各 sub-workflow**

它**不含任何 `process`** —— 全部是 channel 組裝與 sub-workflow 呼叫。

```groovy
 * main_tertiary.nf
 * ================
 * 臨床 WGS/WES 三級分析主 workflow（支援 sample sheet 批次輸入）
 *
 * 支援兩種輸入來源（sample sheet 的 pipeline_type 欄位切換）：
 *
 *   nckuh：NCKUH 二級分析 ensemble VCF
 *     路徑規則：{input_dir}/04_snv_indel/{sample_id}.ensemble.fixed.vcf.gz
 *
 *   dragen：Illumina DRAGEN hard-filtered VCF
 *     路徑規則：{input_dir}/vcf.gz/{sample_id}.hard-filtered.vcf.gz
 *
 * 【設計說明】為什麼用「路徑規則」而不是在 sample sheet 裡直接填 VCF 路徑？
 *   因為一個樣本要用到的檔案不只 SNV VCF —— 還有 mito、STR、CNV、SV、BAM…
 *   六七個檔案。全部填進 sample sheet 會非常冗長且容易填錯。
 *   只填 input_dir，其他由固定規則推導，欄位少、不易錯，
 *   而且二級輸出的目錄結構本來就是固定的。
 *

 *   不傳入 → 要求 sample sheet 內所有 row 的 pipeline_type 一致（否則 error）
 *   傳入   → 只跑符合的 row，不符合的 warn 後跳過
 *
 * 【為什麼不能混跑？】兩條路徑的前處理完全不同（見第 3 章），
 *   在 workflow 層是 if/else 兩個大分支。混在一起會讓 channel 邏輯
 *   複雜到難以維護，而且實務上也不會同時跑兩種來源。
 *
 * Sample sheet 格式（CSV）：
 *   sample_id,pipeline_type,input_dir,seq_type,hpo
 *   NA12878_WES,nckuh,/path/to/nckuh_output,WES,
 *   VAL-10,dragen,/path/to/dragen_output,WGS,HP:0001250|HP:0001263
 *   VAL-11,dragen,/path/to/dragen_output,WGS,
 *     ↑ hpo 欄位保留給未來的表型分析（Exomiser/LIRICAL），目前不使用
 *

 *       --pipeline_type dragen \
 *       --samplesheet all_samples.csv \
 *       --out_dir /home/pipeline/tertiary_output \
 *       -resume
 *

 *   ✅ PREPARE_VCF        - NCKUH ensemble VCF 前處理
 *   ✅ PREPARE_VCF_DRAGEN - DRAGEN VCF 前處理（chrM 分流）
 *   ✅ SNV_ANNOTATE       - VEP 115 annotation
 *   ✅ PARSE_VEP_CSQ      - transcript 選取 + TSV 產生
 *   ✅ ACMG_CLASSIFY      - ACMG evidence 分類
 *   ✅ MITO_ANNOTATE      - mtDNA annotation（VEP + gnomAD-mito，CC0）

nextflow.enable.dsl = 2

// ──────────────────────────────────────────────────────────────
// 匯入 modules
//   命名慣例：ANNOTATE_xxx / PREPARE_xxx = sub-workflow
//   NCKUH / DRAGEN 後綴 = 兩條路徑各自的版本（前處理不同，註解共用）
// ──────────────────────────────────────────────────────────────

include { PREPARE_VCF        } from './modules/prepare_vcf.nf'
include { PREPARE_VCF_DRAGEN; PLOIDY_REPORT_DRAGEN } from './modules/prepare_vcf_dragen.nf'
include { ANNOTATE_SNV       } from './modules/annotate_snv.nf'   // VEP → CSQ → ACMG（兩路共用）
include { MITO_ANNOTATE      } from './modules/mito_annotation.nf'
include { ANNOTATE_STR_NCKUH  } from './modules/str_annotation.nf'
include { ANNOTATE_STR_DRAGEN } from './modules/str_annotation.nf'
include { ANNOTATE_CNV_SV_NCKUH  } from './modules/cnv_sv_annotation.nf'
include { ANNOTATE_CNV_SV_DRAGEN } from './modules/cnv_sv_annotation.nf'

// ──────────────────────────────────────────────────────────────
// Sample sheet 解析
//
// 【為什麼自己寫 parser 而不用 Nextflow 的 splitCsv？】
//   因為需要「開跑前」就完成完整驗證並給出可讀的錯誤訊息
//   （第幾行、哪個欄位、為什麼錯）。splitCsv 產生的是 channel，
//   驗證會發生在 pipeline 已經開始跑之後，錯誤訊息也難以定位到行號。
//   臨床 pipeline 寧可「開跑前就擋下來」，不要跑到一半才發現 sample sheet 有錯。
// ──────────────────────────────────────────────────────────────

def parse_samplesheet(csv_path, pipeline_type_filter = null) {
    /*
     * 解析三級分析 sample sheet（CSV）。
     * 回傳 list of maps，每個 map 對應一個樣本。
     *
     * 必要欄位：sample_id, pipeline_type, input_dir, seq_type
     * 選填欄位：hpo（空白表示無）
     *
     * pipeline_type_filter（來自 --pipeline_type 參數）：
     *   null   → 不過濾，但要求 sample sheet 內所有 row 的 pipeline_type 一致
     *   有值   → 只保留 pipeline_type 符合的 row，不符合的 warn 後跳過
     *
     * 驗證規則：
     *   - 必要欄位不得為空
     *   - pipeline_type 只接受 nckuh 或 dragen
     *   - seq_type 只接受 WES 或 WGS
     *   - sample_id 不得重複
     *   - 過濾後至少要有一個樣本
     */

    def csv_file = file(csv_path)
    if (!csv_file.exists()) {
        error "[ERROR] Sample sheet 不存在：${csv_path}"
    }

    def lines    = csv_file.readLines()
    def header   = lines[0].split(',').collect { it.trim() }
    def samples  = []
    def seen_ids = [] as Set        // Set 用來偵測重複的 sample_id

    // 確認必要欄位存在
    //   錯誤訊息把「現有欄位」也印出來，使用者才知道自己打錯了什麼
    def required_cols = ['sample_id', 'pipeline_type', 'input_dir', 'seq_type']
    for (col in required_cols) {
        if (!header.contains(col)) {
            error "[ERROR] Sample sheet 缺少必要欄位：${col}\n       現有欄位：${header}"
        }
    }

    // 解析每一行
    lines[1..-1].eachWithIndex { line, idx ->
        line = line.trim()
        if (!line || line.startsWith('#')) return  // 跳過空行和 comment
                                                   //   （允許 # 註解，方便暫時停用某些樣本）

        def row_num = idx + 2  // 給使用者看的行號（從 2 開始，1 是 header）
        def values  = line.split(',', -1).collect { it.trim() }
        //                          ↑ limit = -1：保留尾端的空欄位。
        //                            不加的話 "A,B,," 會被切成 ["A","B"]，欄位數對不上。

        // 欄位數量檢查
        if (values.size() < header.size()) {
            // 補齊空欄位
            //   【為什麼要容忍？】使用者用 Excel 存 CSV 時，
            //   最後一欄若為空常常會被省略。這是很常見的情況，不該報錯。
            while (values.size() < header.size()) values << ''
        }

        // 把 header 與 values 配成 map（[sample_id: 'X', pipeline_type: 'nckuh', ...]）
        def row = [header, values].transpose().collectEntries { k, v -> [(k): v] }

        // 必要欄位不得為空
        for (col in required_cols) {
            if (!row[col]) {
                error "[ERROR] Sample sheet 第 ${row_num} 行，欄位 '${col}' 不得為空"
            }
        }

        // pipeline_type 驗證（白名單，不接受任何其他值）
        if (!['nckuh', 'dragen'].contains(row.pipeline_type)) {
            error "[ERROR] Sample sheet 第 ${row_num} 行，pipeline_type '${row.pipeline_type}' 無效\n       只接受：nckuh 或 dragen"
        }

        // seq_type 驗證
        if (!['WES', 'WGS'].contains(row.seq_type)) {
            error "[ERROR] Sample sheet 第 ${row_num} 行，seq_type '${row.seq_type}' 無效\n       只接受：WES 或 WGS"
        }

        // sample_id 重複檢查
        //   【為什麼重要？】重複的 sample_id 會讓兩個樣本的輸出互相覆蓋，
        //   而且 Nextflow 的 join 也會錯配。這是靜默的災難，必須擋下來。
        if (seen_ids.contains(row.sample_id)) {
            error "[ERROR] Sample sheet 第 ${row_num} 行，sample_id '${row.sample_id}' 重複"
        }
        seen_ids << row.sample_id

        // input_dir 存在檢查
        //   只檢查目錄本身；個別檔案的存在檢查在下面建 channel 時做
        //   （因為有些檔案是選用的，缺了只 warn）
        def input_dir = file(row.input_dir)
        if (!input_dir.exists()) {
            error "[ERROR] Sample sheet 第 ${row_num} 行，input_dir 不存在：${row.input_dir}"
        }

        // hpo 預設空字串（保留給未來的表型分析）
        row.hpo = row.hpo ?: ''

        // pipeline_type_filter 過濾（來自 --pipeline_type 參數）
        //   注意這是「warn 後跳過」而不是 error —— 使用者是故意要過濾的
        if (pipeline_type_filter && row.pipeline_type != pipeline_type_filter) {
            log.warn "[WARN] 樣本 ${row.sample_id} 的 pipeline_type=${row.pipeline_type}" +
                     " 不符合 --pipeline_type=${pipeline_type_filter}，跳過"
            return      // Groovy closure 裡的 return = 跳過這一筆，繼續下一筆（相當於 continue）
        }

        samples << row
    }

    if (samples.isEmpty()) {
        error "[ERROR] Sample sheet 沒有任何有效樣本：${csv_path}"
    }

    return samples
}

// ──────────────────────────────────────────────────────────────
// 共用參數驗證（資料庫路徑）
//
// 【必要 vs 選用的分界】
//   必要 = 少了就完全跑不出結果（VEP 不能跑、ACMG 沒有依據）→ error
//   選用 = 少了只是某些欄位變成 "." 或用簡化邏輯 → warn + 降級
// ──────────────────────────────────────────────────────────────

def validate_databases() {
    def checks = [
        ['VEP cache',  params.vep_cache],   // 沒有 → VEP 完全不能跑
        ['dbNSFP',     params.dbnsfp],      // 沒有 → 所有 in-silico 預測都沒有 → PP3/BP4 失效
        ['LOFTEE dir', params.loftee_dir],  // 沒有 → LoF 判斷失效 → PVS1 失效
        ['ClinVar',    params.clinvar],     // 沒有 → 沒有已知致病性參照
    ]
    for (chk in checks) {
        def f = file(chk[1])
        if (!f.exists()) {
            error "[ERROR] ${chk[0]} 不存在：${chk[1]}"
        }
    }

    // Optional 資料庫（只 warn）
    //   ★ 錯誤訊息同時說明「降級後會怎樣」，使用者才能判斷要不要繼續
    if (params.clingen_hi_tsv && !file(params.clingen_hi_tsv).exists()) {
        log.warn "[WARN] ClinGen HI TSV 不存在：${params.clingen_hi_tsv}\n       PVS1 將使用簡化版"
        //  → 沒有單倍體不足（haploinsufficiency）清單，PVS1 無法確認該基因
        //    是否真的是 LoF 致病機轉 → 退回只看 LoF 註記的簡化判斷
    }
    if (params.gene_moi_tsv && !file(params.gene_moi_tsv).exists()) {
        log.warn "[WARN] gene_moi.tsv.gz 不存在：${params.gene_moi_tsv}\n       PM2 將使用純 AF 閾值判斷"
        //  → 沒有遺傳模式（顯性/隱性）資訊，PM2 無法依模式套用不同的 AF 門檻
        //    （隱性疾病的致病變異在族群中可以比顯性的常見得多）
    }
}

// ──────────────────────────────────────────────────────────────
// 主 workflow
// ──────────────────────────────────────────────────────────────


workflow {

    // ── 基本參數檢查 ──────────────────────────────────────────
    if (!params.samplesheet) {
        error "[ERROR] --samplesheet 為必填參數\n       例如：--samplesheet samplesheet_tertiary.csv"
    }
    if (!params.out_dir) {
        error "[ERROR] --out_dir 為必填參數"
    }

    // ── 解析 sample sheet ─────────────────────────────────────
    def samples = parse_samplesheet(params.samplesheet, params.pipeline_type ?: null)

    // ── pipeline_type 決定與一致性檢查 ──────────────────────────
    def pipeline_types = samples.collect { it.pipeline_type }.unique()

    if (!params.pipeline_type && pipeline_types.size() > 1) {
        // 錯誤訊息給出兩種解法，使用者不用猜
        error "[ERROR] Sample sheet 含有多種 pipeline_type：${pipeline_types}\n" +
              "       請拆成兩個 sample sheet 分別執行，\n" +
              "       或用 --pipeline_type 指定要跑的那種（其他 row 會被跳過）"
    }
    def pipeline_type = pipeline_types[0]

    // ── 資料庫路徑驗證 ────────────────────────────────────────
    validate_databases()

    // ── 印出執行資訊 ──────────────────────────────────────────
    // dbNSFP 依 --academic_dbnsfp 切換，banner 必須印「實際使用」的那一個
    //   （評鑑需要能證明這批結果用了哪個版本的資料庫）。
    //
    // ⚠️【Groovy 陷阱】不能寫 `params.academic_dbnsfp as boolean`。
    //   命令列傳進來的 --academic_dbnsfp false 是**字串** "false"，
    //   而 Groovy 對「非空字串」一律判定為 true → 永遠是 true。
    //   必須明確做字串比對。這個坑在本 config 有三處。
    def use_academic  = params.academic_dbnsfp.toString().toLowerCase() == 'true'
    def dbnsfp_in_use = use_academic ? params.dbnsfp_academic : params.dbnsfp
    log.info """
    ╔══════════════════════════════════════════════════════╗
    ║         臨床三級分析 Pipeline  v1.0.0                ║
    ╚══════════════════════════════════════════════════════╝
    Pipeline 類型 : ${pipeline_type.toUpperCase()}
    樣本數        : ${samples.size()}
    Sample sheet  : ${params.samplesheet}
    輸出目錄      : ${params.out_dir}
    容器目錄      : ${params.sif_dir}
    VEP cache     : ${params.vep_cache}
    dbNSFP        : ${dbnsfp_in_use}
    dbNSFP 模式   : ${use_academic ? '5.3a（--academic_dbnsfp 啟用：含 REVEL/MutPred2/VEST4/CADD 與 gnomAD4.1 參考欄）' : '4.9c（預設，全部工具可商用）'}
    ClinVar       : ${params.clinvar}
    ClinGen HI    : ${params.clingen_hi_tsv ?: '（未提供，PVS1 簡化版）'}
    Gene MOI      : ${params.gene_moi_tsv   ?: '（未提供，PM2 純 AF 模式）'}
    PGx           : ${params.run_pgx ? '啟用' : '停用'}（--run_pgx）
    PGx CYP2D6    : ${params.run_pgx_cyp2d6 ? 'StellarPGx BAM-based' : 'VCF only（準確度較低）'}
    PGx HLA       : ${params.run_pgx_hla ? 'OptiType BAM-based' : '停用'}
    """.stripIndent()
    // ★ 這個 banner 是評鑑的重要證物：它把「這批結果用了哪些資料庫版本、
    //   開了哪些選項」寫進 .nextflow.log，永久可追溯。

    // 印出樣本清單
    samples.each { s ->
        log.info "  樣本：${s.sample_id}  seq_type=${s.seq_type}  input=${s.input_dir}"
    }

    // ── BAM channel 預先定義（scope 跨 if/else）────────────────
    //   【為什麼要先宣告？】Groovy 的 if/else 區塊內宣告的 def 變數，
    //   出了區塊就不存在。但 PGx 段落在 if/else 之外還要用它，
    //   所以必須先在外層宣告一個預設值。
    def bam_ch_pgx = Channel.empty()

    // ══════════════════════════════════════════════════════════
    // ── 建立 channel（依 pipeline_type 推導 VCF 路徑）────────
    // ══════════════════════════════════════════════════════════
    if (pipeline_type == 'nckuh') {

        // ── NCKUH 分支 ──
        // NCKUH：{input_dir}/04_snv_indel/{sample_id}.ensemble.fixed.vcf.gz
        //
        // 【為什麼 SNV VCF 缺了要 error 而不是 warn？】
        //   SNV 是主線，沒有它這個樣本就等於沒跑。
        //   缺 mito/STR/CNV 還能交出部分結果，缺 SNV 沒有意義。
        input_ch = Channel.fromList(samples).map { s ->
            def vcf = file("${s.input_dir}/04_snv_indel/${s.sample_id}.ensemble.fixed.vcf.gz")
            def tbi = file("${s.input_dir}/04_snv_indel/${s.sample_id}.ensemble.fixed.vcf.gz.tbi")
            if (!vcf.exists()) {
                error "[ERROR] 找不到 ensemble VCF：${vcf}"
            }
            if (!tbi.exists()) {
                error "[ERROR] 找不到 ensemble VCF index：${tbi}"
            }
            tuple(s.sample_id, vcf, tbi)
        }

        PREPARE_VCF(input_ch)
        snv_ch = PREPARE_VCF.out.snv_ch

        // NCKUH mito：{input_dir}/07_mitochondria/{sample_id}.mito.vcf.gz
        //   二級已經把 chrM 獨立輸出，所以三級直接讀那份
        nckuh_mito_ch = Channel.fromList(samples).map { s ->
            def mito_vcf = file("${s.input_dir}/07_mitochondria/${s.sample_id}.mito.vcf.gz")
            def mito_tbi = file("${s.input_dir}/07_mitochondria/${s.sample_id}.mito.vcf.gz.tbi")
            if (!mito_vcf.exists()) {
                log.warn "[WARN] 找不到 mito VCF，跳過：${mito_vcf}"
                return null              // 回傳 null 標記為「要跳過」
            }
            tuple(s.sample_id, "nckuh", mito_vcf, mito_tbi)
            //                  ↑ 帶上來源標記，MITO_ANNOTATE 內部依此走不同解析邏輯
        }
        .filter { it != null }           // 把 null 濾掉 → 該樣本自然不會產生 task

        MITO_ANNOTATE(nckuh_mito_ch)

        // NCKUH STR：{input_dir}/06_repeat/{sample_id}.str.vcf（未壓縮）
        //   ★ 注意是「未壓縮」—— GangSTR 的合併輸出沒有壓縮（見二級大補帖第 9 章）
        nckuh_str_ch = Channel.fromList(samples).map { s ->
            def str_vcf = file("${s.input_dir}/06_repeat/${s.sample_id}.str.vcf")
            if (!str_vcf.exists()) {
                log.warn "[WARN] 找不到 STR VCF，跳過：${str_vcf}"
                return null
            }
            tuple(s.sample_id, str_vcf)
        }
        .filter { it != null }

        ANNOTATE_STR_NCKUH(nckuh_str_ch)

        // ── NCKUH CNV/SV annotation（sub-workflow）────────────────
        //   CNV 依 seq_type 分流：WES→gCNV VCF、WGS→CNVkit .call.cns（先轉 BED）；
        //   SV→Delly（WES+WGS 共用）。無對應樣本時該 channel 為空 → 對應 process 0 task，
        //   不需再用 if (seq_types.contains(...)) 包起來。
        //
        // 【這個設計要點值得記住】「空 channel = 0 個 task」是 Nextflow 的自然行為，
        //   所以不需要寫 if 判斷。全 WGS 的批次跑起來，gCNV 那一路就是 0 task，
        //   DAG 上顯示為 `-`。這比寫 if 更簡潔，也不會有「條件寫錯導致該跑的沒跑」。
        nckuh_cnv_wes_ch = Channel.fromList(samples)
            .filter { s -> s.seq_type == "WES" }        // 只有 WES 有 gCNV
            .map { s ->
                def vcf = file("${s.input_dir}/05_cnv_sv/${s.sample_id}.gcnv.vcf.gz")
                def tbi = file("${s.input_dir}/05_cnv_sv/${s.sample_id}.gcnv.vcf.gz.tbi")
                if (!vcf.exists()) {
                    log.warn "[WARN] 找不到 gCNV VCF，跳過：${vcf}"
                    return null
                }
                tuple(s.sample_id, vcf, tbi)
            }
            .filter { it != null }

        nckuh_cnvkit_ch = Channel.fromList(samples)
            .filter { s -> s.seq_type == "WGS" }        // 只有 WGS 跑 CNVkit
            .map { s ->
                def cns = file("${s.input_dir}/05_cnv_sv/${s.sample_id}.call.cns")
                if (!cns.exists()) {
                    log.warn "[WARN] 找不到 CNVkit .call.cns，跳過：${cns}"
                    return null
                }
                tuple(s.sample_id, cns)
            }
            .filter { it != null }

        // SV（Delly）：WES + WGS 都有，不需要 filter
        nckuh_sv_ch = Channel.fromList(samples).map { s ->
            def vcf = file("${s.input_dir}/05_cnv_sv/${s.sample_id}.delly.vcf.gz")
            def tbi = file("${s.input_dir}/05_cnv_sv/${s.sample_id}.delly.vcf.gz.tbi")
            if (!vcf.exists()) {
                log.warn "[WARN] 找不到 Delly VCF，跳過：${vcf}"
                return null
            }
            tuple(s.sample_id, vcf, tbi)
        }
        .filter { it != null }

        ANNOTATE_CNV_SV_NCKUH(nckuh_cnv_wes_ch, nckuh_cnvkit_ch, nckuh_sv_ch)

        // ── NCKUH BAM channel（PGx 全樣本，含 WES + WGS）────────
        // WGS：StellarPGx + OptiType + GATK gVCF
        // WES：GATK gVCF（StellarPGx/OptiType 在 pgx_annotation.nf 內自動跳過）
        // BAM 路徑：{input_dir}/02_alignment/{sample_id}.aligned.sorted.bam
        //
        // 【為什麼 WES 不跑 StellarPGx / OptiType？】
        //   StellarPGx 需要 CYP2D6 全基因座的均勻覆蓋來解結構變異
        //   （CYP2D6 有大量的雜合基因與拷貝數變化）；
        //   OptiType 需要 HLA 區域的完整覆蓋。WES 捕捉套組對這兩個區域
        //   的覆蓋都不完整，跑出來的結果不可信。
        bam_ch_pgx = Channel.fromList(samples)
            .map { s ->
                def bam = file("${s.input_dir}/02_alignment/${s.sample_id}.aligned.sorted.bam")
                def bai = file("${s.input_dir}/02_alignment/${s.sample_id}.aligned.sorted.bam.bai")
                if (!bam.exists()) {
                    log.warn "[WARN] 找不到 BAM，PGx gVCF 跳過（PharmCAT 改用 SNV VCF 模式）：${bam}"
                    return null
                }
                tuple(s.sample_id, s.seq_type, bam, bai)
                //                  ↑ 帶著 seq_type，PGx 段落要用它分流
            }
            .filter { it != null }

    } else {

        // ── DRAGEN 分支 ──
        // DRAGEN：{input_dir}/vcf.gz/{sample_id}.hard-filtered.vcf.gz
        //   ★ 沒有 .tbi —— DRAGEN 的 VCF index 是 .csi 或根本沒有，
        //     PREPARE_VCF_DRAGEN 內部會自己建
        input_ch = Channel.fromList(samples).map { s ->
            def vcf = file("${s.input_dir}/vcf.gz/${s.sample_id}.hard-filtered.vcf.gz")
            if (!vcf.exists()) {
                error "[ERROR] 找不到 DRAGEN VCF：${vcf}"
            }
            tuple(s.sample_id, vcf)
        }

        PREPARE_VCF_DRAGEN(input_ch)
        snv_ch = PREPARE_VCF_DRAGEN.out.snv_ch

        // ── DRAGEN ploidy QC（性別 + aneuploidy，來自 DRAGEN 原生 ploidy.vcf）──
        //   與二級 PLOIDY_CHECK 同一套 qc.txt 呈現；ploidy.vcf 不存在則 warn 後跳過。
        //
        // 【為什麼 DRAGEN 的倍體 QC 在三級做？】DRAGEN 自己就會輸出 ploidy.vcf，
        //   不需要重新計算深度。三級只要解析它、轉成與二級一致的 QC 格式即可。
        //   兩條路徑的 ploidy_qc.txt 格式相同 → 判讀者不用學兩套。
        ch_dragen_ploidy_py = file("${params.scripts_dir}/parse_dragen_ploidy.py")
        dragen_ploidy_ch = Channel.fromList(samples).map { s ->
            def pvcf = file("${s.input_dir}/vcf.gz/${s.sample_id}.ploidy.vcf.gz")
            if (!pvcf.exists()) {
                log.warn "[WARN] 找不到 DRAGEN ploidy VCF，跳過 ploidy QC：${pvcf}"
                return null
            }
            tuple(s.sample_id, pvcf)
        }
        .filter { it != null }

        PLOIDY_REPORT_DRAGEN(dragen_ploidy_ch, ch_dragen_ploidy_py)

        // DRAGEN 的 chrM 混在主 VCF 裡 → PREPARE_VCF_DRAGEN 已經分流出來
        //   （這是 DRAGEN 路徑與 NCKUH 路徑最大的結構差異）
        dragen_mito_ch = PREPARE_VCF_DRAGEN.out.mito_ch.map { sample_id, mito_vcf, mito_tbi ->
            tuple(sample_id, "dragen", mito_vcf, mito_tbi)
        }

        MITO_ANNOTATE(dragen_mito_ch)

        dragen_str_ch = Channel.fromList(samples).map { s ->
            def str_vcf = file("${s.input_dir}/vcf.gz/${s.sample_id}.repeats.vcf.gz")
            if (!str_vcf.exists()) {
                log.warn "[WARN] 找不到 STR VCF，跳過：${str_vcf}"
                return null
            }
            tuple(s.sample_id, str_vcf)
        }
        .filter { it != null }

        ANNOTATE_STR_DRAGEN(dragen_str_ch)

        // ── DRAGEN CNV/SV annotation（sub-workflow）────────────────
        //   CNV：PASS + 去 copy-neutral → AnnotSV；SV：PASS + INS symbolic → AnnotSV。
        dragen_cnv_ch = Channel.fromList(samples).map { s ->
            def vcf = file("${s.input_dir}/vcf.gz/${s.sample_id}.cnv.vcf.gz")
            if (!vcf.exists()) {
                log.warn "[WARN] 找不到 DRAGEN CNV VCF，跳過：${vcf}"
                return null
            }
            tuple(s.sample_id, vcf)
        }
        .filter { it != null }

        dragen_sv_ch = Channel.fromList(samples).map { s ->
            def vcf = file("${s.input_dir}/vcf.gz/${s.sample_id}.sv.vcf.gz")
            if (!vcf.exists()) {
                log.warn "[WARN] 找不到 DRAGEN SV VCF，跳過：${vcf}"
                return null
            }
            tuple(s.sample_id, vcf)
        }
        .filter { it != null }

        ANNOTATE_CNV_SV_DRAGEN(dragen_cnv_ch, dragen_sv_ch)

        // ── DRAGEN BAM channel（PGx 全樣本，含 WES + WGS）────────
        // DRAGEN 輸出 BAM 路徑依版本可能不同，嘗試兩個慣用路徑
        //   【為什麼要試兩個？】DRAGEN 的輸出結構在不同版本間變過：
        //   舊版直接放在輸出根目錄，新版收在 bam/ 子目錄。
        //   兩個都試，使用者不用管自己用的是哪一版。
        bam_ch_pgx = Channel.fromList(samples).map { s ->
            def bam = file("${s.input_dir}/bam/${s.sample_id}.bam")
            def bai = file("${s.input_dir}/bam/${s.sample_id}.bam.bai")
            if (!bam.exists()) {
                // 備用路徑（DRAGEN 直接放上層目錄）
                bam = file("${s.input_dir}/${s.sample_id}.bam")
                bai = file("${s.input_dir}/${s.sample_id}.bam.bai")
            }
            if (!bam.exists()) {
                log.warn "[WARN] 找不到 DRAGEN BAM，PGx gVCF 跳過（PharmCAT 改用 SNV VCF 模式）：${bam}"
                return null
            }
            tuple(s.sample_id, s.seq_type, bam, bai)
        }
        .filter { it != null }
    }

    // ══════════════════════════════════════════════════════════
    // ── 兩條路徑在此合流 ──
    // ══════════════════════════════════════════════════════════

    // ── SNV annotation 尾段（sub-workflow：VEP → CSQ parse → ACMG，兩 pipeline 共用）──
    //
    // 【NO_FILE 哨兵值】Nextflow 的 path input 不接受 null。
    //   選用檔案不存在時傳一個不存在的假檔名，process 內用
    //   `xxx.name != 'NO_FILE'` 判斷要不要用它。
    //   （與二級 mosdepth 的 targets 是同一個技巧）
    def clingen_hi_file = (params.clingen_hi_tsv && file(params.clingen_hi_tsv).exists())
        ? file(params.clingen_hi_tsv)
        : file("NO_FILE")

    def gene_moi_file = (params.gene_moi_tsv && file(params.gene_moi_tsv).exists())
        ? file(params.gene_moi_tsv)
        : file("NO_FILE")

    ANNOTATE_SNV(snv_ch, clingen_hi_file, gene_moi_file)

    // ── PGx annotation（PharmCAT + StellarPGx）────────────────
    // --run_pgx false（預設）→ 跳過
    //   ⚠️ 註解略舊：config 裡 run_pgx 實際預設是 true
    // --run_pgx true  → 啟用；WGS 走 StellarPGx（CYP2D6 BAM-based），WES 直接 VCF
    if (params.run_pgx) {

        // pipeline_type lookup channel（從 samples 建立）
        //   PGX_ANNOTATE 內部需要知道每個樣本是 nckuh 還是 dragen
        //   （DRAGEN 才有 targeted.json 可以交叉比對）
        ptype_ch = Channel.fromList(samples)
            .map { s -> tuple(s.sample_id, s.pipeline_type) }

        // ── 三種 PGx 執行情境，各建一條 channel ──
        //
        // bam_ch_pgx = tuple(sid, seq_type, bam, bai)
        // WGS：帶 BAM 進去，StellarPGx + OptiType + gVCF 在 PGX_ANNOTATE 內部跑
        pgx_wgs_ch = snv_ch
            .join(bam_ch_pgx.filter { sid, seq_type, bam, bai -> seq_type == "WGS" })
            .join(ptype_ch)
            .map { sid, vcf, tbi, seq_type, bam, bai, ptype ->
                tuple(sid, ptype, vcf, tbi, bam, bai)
            }

        // WES with BAM：有 BAM，跑 gVCF，跳過 StellarPGx/OptiType
        //   （形狀與 WGS 相同，但 PGX_ANNOTATE 內部依 seq_type 決定跑什麼）
        pgx_wes_bam_ch = snv_ch
            .join(bam_ch_pgx.filter { sid, seq_type, bam, bai -> seq_type == "WES" })
            .join(ptype_ch)
            .map { sid, vcf, tbi, seq_type, bam, bai, ptype ->
                tuple(sid, ptype, vcf, tbi, bam, bai)
            }

        // WES without BAM：沒有 BAM，純 VCF 模式
        //
        // 【join(remainder: true) 的用法】一般的 join 只發射「兩邊都有」的 key。
        //   加上 remainder: true 後，只有左邊有的 key 也會發射，
        //   右邊的欄位補成 null。所以 `vals[3] == null` 就是
        //   「這個樣本在 snv_ch 有、但在 bam_ch_pgx 沒有」= 沒有 BAM。
        pgx_wes_ch = snv_ch
            .join(bam_ch_pgx, remainder: true)
            .filter { vals -> vals[3] == null }   // 沒有 BAM 的樣本
            .join(ptype_ch)
            .map { vals ->
                def sid   = vals[0]
                def vcf   = vals[1]
                def tbi   = vals[2]
                def ptype = vals[4]        // vals[3] 是 null（seq_type 的位置）
                tuple(sid, ptype, vcf, tbi)
            }

        // DRAGEN 原生 PGx 判讀（targeted.json）channel；非 DRAGEN 為空。交叉註記在 PGX_ANNOTATE 內做。
        //   路徑：{input_dir}/other/{sample_id}/germline_seq/{sample_id}.targeted.json
        //   找不到就 warn 後跳過（該樣本保留基礎版 pgx.tsv，不報錯）。欄位不變。
        //
        // 【這是什麼？】DRAGEN 自己也會做 PGx 判讀，結果放在 targeted.json。
        //   我們把它與自己用 PharmCAT 算出來的結果比對，在 NOTES 欄註記
        //   「DRAGEN 一致 / 不一致（附 DRAGEN 的原始基因型）/ 未比對」。
        //   ★ 欄位結構完全不變，只多寫 NOTES → 下游 GUI 不用改。
        dragen_targeted_ch = (pipeline_type == 'dragen')
            ? Channel.fromList(samples).map { s ->
                  def tj = file("${s.input_dir}/other/${s.sample_id}/germline_seq/${s.sample_id}.targeted.json")
                  if (!tj.exists()) {
                      log.warn "[WARN] 找不到 DRAGEN targeted.json，跳過 PGx 交叉註記：${tj}"
                      return null
                  }
                  tuple(s.sample_id, tj)
              }.filter { it != null }
            : Channel.empty()      // NCKUH 路徑：空 channel → 交叉比對 0 task

        PGX_ANNOTATE(
            pgx_wgs_ch,
            pgx_wes_bam_ch.mix(pgx_wes_ch),      // 兩種 WES 情境合成一條
            MITO_ANNOTATE.out.mito_tsv_ch.ifEmpty(Channel.empty()),
            //   ↑ ifEmpty：mito 全部跳過時給一個空 channel，避免 PGX_ANNOTATE 卡住等輸入
            dragen_targeted_ch
        )
    }
}
```

# 第 2 章：`nextflow_tertiary.config` — 執行環境與資料庫

## 2.1 ⚠️ 最重要的坑：`params` 區塊在 `profiles` 後面

**與二級 config 是同一個坑，而且這裡踩過兩次。**

Nextflow 讀 config 由上而下依序賦值，**後面的覆蓋前面的**。
本檔 `profiles {}` 在前、全域 `params {}` 在後，所以：

> **任何在全域 `params {}` 裡宣告的參數，都會蓋掉 profile 裡設的值。**

**踩過的實例**：
- `use_gpu_lock` 曾經同時在 profile 與全域宣告 → `dgx` profile 設的 `true` 被全域的 `false` 蓋掉 → GPU 鎖完全沒作用
- `stellarpgx_repo` 同理，所以檔案裡明確註記「不在此宣告」

**規則**：
- **環境相依**的參數（`ref_dir`、`sif_dir`、`scripts_dir`、`out_dir`、`use_gpu_lock`、
  `use_gpu_pangolin`、`pangolin_num_gpus`、`stellarpgx_repo`）→ **只寫在 profile**
- **不分環境**的常數與**由根目錄推導**的路徑 → 寫在全域 `params {}`

## 2.2 ⚠️ 第二個坑：Groovy 對字串 `"false"` 判定為 true

命令列傳進來的 `--academic_dbnsfp false` 是**字串** `"false"`，不是布林值。
Groovy 的真值判斷對「非空字串」一律回傳 `true`。

```groovy
params.academic_dbnsfp as boolean            // ❌ 字串 "false" → true
params.academic_dbnsfp.toString().toLowerCase() == 'true'   // ✅ 正確
```

本 pipeline 有三處用到這個模式：`academic_dbnsfp`（banner + `snv_annotation.nf`）、
`use_gpu_pangolin`（三個 profile 的 `containerOptions`）。

# 第 3 章：輸入前處理（兩條路徑）

## 3.1 兩條路徑要解決的問題不同

| | NCKUH `prepare_vcf.nf` | DRAGEN `prepare_vcf_dragen.nf` |
|---|---|---|
| 輸入形狀 | **兩個樣本欄**（`_DV` + `_HC`） | 單一樣本欄 |
| 要做的事 | 把「哪個 caller 叫到」壓成 INFO tag | 把 FORMAT 欄搬到 INFO；chrM 分流 |
| phasing/combine | 二級已做完 | **這裡做**（用 DRAGEN 原生 PS） |
| chrM | 二級已分開輸出 | **混在主 VCF 裡，要分流** |
| 過濾 | 依 `CALLERS` tag（不是 `FILTER`） | 依 `FILTER=PASS`（chrM 除外） |
| 倍體 QC | 二級做 | `PLOIDY_REPORT_DRAGEN` |

**共同點**：兩者都先跑 `bcftools norm -m -any`（左對齊 + 拆多等位）。

## 3.2 ⚠️ 為什麼一定要先 `norm -m -any`

```bash
bcftools norm -m -any -f ${ref_fasta} -c w input.vcf.gz -Oz -o norm.vcf.gz
```

三件事：

1. **`-m -any` 拆多等位** —— 一個位點若有兩個 ALT（`A > G,T`），
   VEP 的註解、gnomAD 的頻率、ClinVar 的致病性都是**per-allele** 的。
   不拆開，兩個 ALT 的註解會混在同一列，判讀者無法分辨哪個註解屬於哪個 ALT。
2. **左對齊（left-align）** —— indel 在重複序列中有多種等價的表示法。
   VCF 規範要求「最左表示」，資料庫也都是用最左表示建索引。
   不對齊就會查不到 ClinVar/gnomAD。
3. **`-c w`** —— REF 與參考序列不符時只警告不中斷。
   （同一份 hg38 下通常不會發生，但若二級與三級用了不同的參考版本，
   這裡會警告而不是整個掛掉。）

## 3.3 ⚠️ NCKUH 路徑最重要的決定：用 `CALLERS` 而不是 `FILTER` 過濾

**背景**：二級 ensemble VCF 的 `FILTER` 欄語義是：

| FILTER | 意義 |
|--------|------|
| `PASS` | DeepVariant 有 call（DV+HC 或 DV-only） |
| `RefCall` | DV 叫 0/0（HC 可能有 call、也可能是 `./.`） |
| `.` | 兩個 caller 都沒 call |

**如果照直覺用 `FILTER="PASS"` 過濾會怎樣？**

> **所有 HC-only 的變異全部被丟掉。**
> NA12878_WES 實測：HC-only 佔 **23.9%（8,897 / 37,198）**。

這違反 joint calling 的基本原則（「只要有一個 caller 叫到就保留，
由下游判讀」），而且會靜默地少掉近四分之一的變異。

**修正**：`add_callers_tag.py` 依 **GT 欄位**判斷每個 caller 的實際 call 狀態，
寫成 `INFO/CALLERS`，過濾改用 `CALLERS`：

```bash
bcftools view -i 'INFO/CALLERS="DV+HC" || INFO/CALLERS="DV" || INFO/CALLERS="HC"'
```

「`CALLERS` 有值」⟺「至少一個 caller 有有效的 ALT call」。
`DV=0/0, HC=./.` 這種兩邊都沒 call 的位點，`is_called()` 兩邊都回 `False`，
不會被保留。

## 3.4 `modules/prepare_vcf.nf` 全文逐行註解

```groovy
/*
 * =========================================================
 * WGS/WES Germline Analysis Pipeline - CNV/SV Module
 *   ★ 檔頭標題寫錯了（是 prepare_vcf 不是 CNV/SV），複製貼上的殘留。
 *     不影響行為，但值得修。
 * =========================================================
 * Author   : Po-Yu Lin (林伯昱)
 * （GPL-3.0-or-later 與免責宣告同 main_tertiary.nf，此處省略）
 * =========================================================
 * modules/prepare_vcf.nf
 * ======================
 * 目的：
 *   將二級分析產生的 ensemble.fixed.vcf.gz（雙 sample column：_DV + _HC）
 *   處理為三級分析 VEP annotation 的輸入，共兩個步驟：
 *
 *   Step 1 - ADD_CALLERS_TAG：
 *     執行 add_callers_tag.py，在 INFO 欄位新增 CALLERS tag（DV+HC/DV/HC）
 *
 *   Step 2 - FILTER_FOR_ANNOTATION：
 *     用 bcftools 過濾掉不適合送進 VEP 的 variant：
 *       - RefCall（FILTER=RefCall，DV 叫 0/0 但 HC 叫 ./. 的情況）
 *       - 兩個 sample column 都是 0/0 或 ./. 的 variant
 *     同時 bgzip 壓縮 + tabix index，產生標準的 .vcf.gz + .tbi
 *
 * 輸入（來自 main_tertiary.nf）：
 *   tuple val(sample_id), path(ensemble_vcf), path(ensemble_tbi)
 *
 * 輸出：
 *   tuple val(sample_id), path("*.snv_for_annotation.vcf.gz"), path("*.snv_for_annotation.vcf.gz.tbi")
 *
 * 使用的容器：
 *   Step 1：tertiary_python_1.0.0.sif（含 cyvcf2）
 *   Step 2：bcftools_1.23.1.sif
 *   ★ 為什麼分兩個 process？因為一個 process 只能指定一個容器
 *     （與二級粒線體流程被迫拆成 12 個 process 是同一個限制）。
 */

// ──────────────────────────────────────────────────────────────
// Process 1：新增 CALLERS tag
// ──────────────────────────────────────────────────────────────

process ADD_CALLERS_TAG {
    // 標籤：對應 nextflow_tertiary.config 的資源設定
    label 'process_low'

    // 使用 tertiary_python sif（含 cyvcf2）
    //   ★ 三級的容器直接寫在 process 裡（用 params.sif_dir 組路徑），
    //     不像二級集中在 config 的 withName。兩種做法各有優缺：
    //     寫在 process 裡 → 看程式碼就知道用什麼容器
    //     寫在 config 裡   → 換容器不用動程式碼
    container "${params.sif_dir}/tertiary_python_1.0.0.sif"

    // 輸入：ensemble VCF + 其 index
    input:
    tuple val(sample_id), path(ensemble_vcf), path(ensemble_tbi)

    // 輸出：加上 CALLERS tag 的未壓縮 VCF（暫時檔，交給下一個 process）
    output:
    tuple val(sample_id), path("${sample_id}.callers_tagged.vcf")

    script:
    """
    # 先正規化 + 拆分多等位基因（left-align + split multiallelics）。
    # 讓每個 ALT 各自一列，使 CALLERS/AD/VAF 以及後續 VEP / gnomAD / ClinVar 註解
    # 都是 per-allele 正確（避免多等位基因位點把不同 allele 的 AF / 致病性混在一起）。
    # -c w：REF 與參考不符時只警告不中斷（同一 hg38 參考下通常不會發生）。
    #
    # 【與二級的關係】二級的 BCFTOOLS_ENSEMBLE 已經跑過 norm -m -any 了，
    #   所以這一步在 NCKUH 路徑上實質是冪等的（no-op）。
    #   保留它是為了防禦：萬一輸入不是二級的標準輸出（例如手動修過的 VCF），
    #   這一步能保證下游拿到的一定是 biallelic + 左對齊的。
    bcftools norm -m -any -f ${params.ref_fasta} -c w \\
        ${ensemble_vcf} \\
        -Oz -o ${sample_id}.norm.vcf.gz

    # 執行 add_callers_tag.py（吃正規化後的 biallelic VCF）
    # --sample 傳入 sample_id，腳本會自動尋找 {sample_id}_DV 和 {sample_id}_HC column
    python3 ${params.scripts_dir}/add_callers_tag.py \\
        --input  ${sample_id}.norm.vcf.gz \\
        --sample ${sample_id} \\
        --output ${sample_id}.callers_tagged.vcf
    """
    //  ⚠️ 這裡用 ${params.scripts_dir}/… 直接呼叫，不是 staged path input。
    //     代價：改了 add_callers_tag.py 之後，-resume 不會偵測到變更，
    //     會沿用舊快取。（COMBINE_DRAGEN 與 PLOIDY_REPORT_DRAGEN 已改成 staged，
    //     這支還沒。改 script 後要用 -resume 記得先手動刪 work 目錄。）
}

// ──────────────────────────────────────────────────────────────
// Process 2：過濾 + bgzip + tabix
// ──────────────────────────────────────────────────────────────

process FILTER_FOR_ANNOTATION {
    label 'process_low'

    // 使用既有的 bcftools sif
    container "${params.sif_dir}/bcftools_1.23.1.sif"

    // publishDir：將最終輸出複製到三級分析輸出目錄
    // mode: 'copy' 確保輸出目錄有獨立的檔案（不是 symlink）
    publishDir "${params.out_dir}/${sample_id}/00_prepare", mode: 'copy'

    input:
    tuple val(sample_id), path(callers_tagged_vcf)

    // 輸出：bgzip 壓縮的 VCF + tabix index
    output:
    tuple val(sample_id),
          path("${sample_id}.snv_for_annotation.vcf.gz"),
          path("${sample_id}.snv_for_annotation.vcf.gz.tbi")

    script:
    """
    # ★★ 以下這段註解是整個檔案最重要的內容 —— 它記錄了一個
    #    「照直覺做會靜默丟掉 24% 變異」的陷阱。★★
    #
    # 過濾策略：依據 CALLERS tag 過濾，不使用 FILTER 欄位。
    #
    # 背景：
    #   ensemble VCF 的 FILTER 欄位由二級分析設定，語義如下：
    #     FILTER=PASS    → DV 有 call（DV+HC 或 DV-only）
    #     FILTER=RefCall → DV 叫 0/0（HC 可能有 call 也可能是 ./.）
    #     FILTER=.       → 兩個 caller 都沒有 call
    #
    # 問題：
    #   用 FILTER="PASS" 過濾會把所有 HC-only variant（FILTER=RefCall）
    #   全部丟掉，違反 joint calling「只要有一個 caller call 到就保留」的規則。
    #   NA12878_WES 測試確認：HC-only 佔 23.9%（8,897/37,198 個），不應被丟棄。
    #
    # 修正：
    #   add_callers_tag.py 已根據 GT 欄位正確判斷每個 variant 的 call 狀態：
    #     CALLERS=DV+HC → 兩個都有 ALT call，來自 FILTER=PASS
    #     CALLERS=DV    → 只有 DV 有 ALT call，來自 FILTER=PASS
    #     CALLERS=HC    → 只有 HC 有 ALT call，來自 FILTER=RefCall（HC=0/1）
    #   RefCall 中 DV=0/0, HC=./. 的 variant，CALLERS 被判為 HC（但 is_called 回傳 False）
    #   → 實際上這種 case 兩個 caller 都沒有 call，不會有 CALLERS tag。
    #   所以只要 CALLERS 有值，就代表至少一個 caller 有有效的 ALT call。

    bcftools view \\
        -i 'INFO/CALLERS="DV+HC" || INFO/CALLERS="DV" || INFO/CALLERS="HC"' \\
        ${callers_tagged_vcf} \\
        -Oz -o ${sample_id}.snv_for_annotation.vcf.gz
        #  -i = include（只保留符合條件的）
        #  三個條件用 || 串起來，等同於「CALLERS 欄位有值」

    # 建立 tabix index（VEP 和後續工具都需要）
    tabix -p vcf ${sample_id}.snv_for_annotation.vcf.gz

    # 輸出統計（寫進 log，方便 debug）
    #   ★ bcftools stats 的 SN 行含變異總數、SNP 數、indel 數等。
    #     每次執行都印到 .command.err，是「這一步到底留下多少變異」的直接證據。
    echo "[FILTER_FOR_ANNOTATION] ${sample_id}" >&2
    bcftools stats ${sample_id}.snv_for_annotation.vcf.gz | \\
        grep "^SN" >&2
    """
}

// ──────────────────────────────────────────────────────────────
// 組合 workflow（供 main_tertiary.nf 呼叫）
// ──────────────────────────────────────────────────────────────

workflow PREPARE_VCF {
    // 輸入 channel：tuple(sample_id, ensemble_vcf, ensemble_tbi)
    take:
    ensemble_ch

    // 執行兩個 process，串接輸出
    main:
    ADD_CALLERS_TAG(ensemble_ch)
    FILTER_FOR_ANNOTATION(ADD_CALLERS_TAG.out)

    // 輸出 channel：tuple(sample_id, snv_vcf, snv_tbi)
    emit:
    snv_ch = FILTER_FOR_ANNOTATION.out
}
```

```python
"""
 * =========================================================
 * WGS/WES Germline Analysis Pipeline
 * =========================================================
 * Author   : Po-Yu Lin (林伯昱)
 * （GPL-3.0-or-later、第三方授權、免責宣告同 main_tertiary.nf，此處省略）

    DV     → 只有 DeepVariant call

使用方式（由 Nextflow module prepare_vcf.nf 呼叫）：
    ...（範例略，與下方 epilog 重複）

    pip install cyvcf2   （比 pysam 更快，處理大型 VCF 效率更好）

# ⚠️ 這個檔案有「兩份 docstring」—— 第二份是後來擴充功能時新增的，
#    第一份忘了刪。Python 只會把第一個字串當 __doc__，第二個是無害的
#    獨立字串運算式。不影響行為，但值得清理。
#    第二份的內容比較新（多了 DP/AD/VAF 的說明），所以保留在這裡：

#!/usr/bin/env python3
"""
add_callers_tag.py
==================
目的：
    將二級分析產生的 ensemble.fixed.vcf.gz（含兩個 sample column：
    {SAMPLE_ID}_DV 和 {SAMPLE_ID}_HC）處理為三級分析可用的單一樣本 VCF。

    在 INFO 欄位新增以下 tag：
        CALLERS   → 哪些 caller 偵測到此 variant（DV+HC / DV / HC）
        DP_DV     → DeepVariant 的 read depth
        AD_DV     → DeepVariant 的 allelic depth（REF,ALT 逗號分隔）
        VAF_DV    → DeepVariant 的 variant allele fraction
        DP_HC     → HaplotypeCaller 的 read depth
        AD_HC     → HaplotypeCaller 的 allelic depth（REF,ALT 逗號分隔）

    為何保留兩個 caller 的 DP/AD：
        - 臨床審閱時可以比較兩個 caller 的支持度
        - DV 和 HC 的 DP 定義略有不同（DV 計算方式更保守）
        - AD 可以用來計算 VAF，確認 zygosity
        ★ 這是關鍵設計：把「兩個樣本欄」壓成「一個樣本 + 兩組 INFO tag」，
          既讓下游只要處理單樣本 VCF（VEP 只吃單樣本），
          又不丟失任何一個 caller 的深度資訊。

使用方式（由 Nextflow module prepare_vcf.nf 呼叫）：
    ...

依賴：
    pip install cyvcf2
"""

import argparse
import math
import sys

try:
    from cyvcf2 import VCF, Writer
except ImportError:
    # 給出可執行的修復指令，而不是只丟一個 ImportError stack trace
    print("[ERROR] 請先安裝 cyvcf2：pip install cyvcf2", file=sys.stderr)
    sys.exit(1)
# 【為什麼用 cyvcf2 而不是 pysam？】cyvcf2 是 htslib 的薄封裝（Cython），
#   逐 variant 迭代的速度比 pysam 快 3–5 倍。WGS 的 VCF 有 400–500 萬列，
#   這個差距是「5 分鐘 vs 25 分鐘」。


# ──────────────────────────────────────────────
# GT 判斷
# ──────────────────────────────────────────────

def is_called(gt_tuple) -> bool:
    """
    判斷一個 sample 的 GT 是否為有效的 variant call。

    cyvcf2 genotypes 格式：[allele1, allele2, phased]
        allele = -1 → missing（.）
        allele =  0 → REF
        allele >= 1 → ALT

    ★ 這個函式就是 3.3 所說「依 GT 判斷」的實作核心。
      三種情況都回傳 False（= 沒有 call）：
        1. gt_tuple 是 None（該樣本欄根本不存在）
        2. 任一 allele 是 -1（./. 或 ./1 這種半缺失）
        3. 兩個 allele 都是 0（0/0，明確叫成 ref）
      其餘（0/1、1/1、1/2…）都算有 call。
    """
    if gt_tuple is None:
        return False
    a1, a2 = gt_tuple[0], gt_tuple[1]
    if a1 == -1 or a2 == -1:
        return False
    if a1 == 0 and a2 == 0:
        return False
    return True


def determine_callers(variant, dv_idx: int, hc_idx: int) -> str:
    """DV 和 HC 的 call 狀態 → CALLERS 字串"""
    dv_called = is_called(variant.genotypes[dv_idx])
    hc_called = is_called(variant.genotypes[hc_idx])

    if dv_called and hc_called:
        return "DV+HC"
    elif dv_called:
        return "DV"
    else:
        return "HC"
    # ⚠️ 注意最後的 else：「DV 沒 call」就回傳 "HC"，
    #    即使 HC 也沒 call。這看起來像 bug，但實務上不會發生 ——
    #    因為 ensemble VCF 只保留「至少一個 caller 有記錄」的位點，
    #    而 bcftools merge 不會產生兩邊都是 0/0 的列。
    #    prepare_vcf.nf 的註解也記錄了這個推論。
    #    （若真的出現，那一列會被標成 HC 並保留 —— 屬於「寧可多留」的保守行為。）


# ──────────────────────────────────────────────
# FORMAT 欄位擷取輔助函式
#
# 三個函式的共同模式：
#   1. 用 try/except 包起來 —— 欄位不存在時 cyvcf2 會拋例外
#   2. 檢查 missing 值 —— cyvcf2 用特殊數值表示 missing，不是 None
#   3. 一律回傳「字串」—— 包含 "." 表示 missing
#      （因為要寫進 INFO，而我們把這些 tag 都宣告成 Type=String）
#
# 【為什麼 INFO tag 宣告成 String 而不是 Integer/Float？】
#   因為要能表示 "."（missing）。若宣告成 Integer，
#   cyvcf2 寫入時會需要真正的整數，"." 會出錯。
#   宣告成 String 讓「有值」與「沒值」用同一種方式處理，最簡單也最不會錯。
# ──────────────────────────────────────────────

def get_dp(variant, sample_idx: int) -> str:
    """
    從 FORMAT/DP 取得 read depth。
    回傳字串，missing 時回傳 "."

    cyvcf2 integer missing value 為 -2147483648（INT_MIN）。
      ★ 所以判斷 missing 用 `val < 0` —— 深度不可能是負數，
        任何負值都代表 missing。
    """
    try:
        dp = variant.format("DP")
        if dp is None:
            return "."
        val = dp[sample_idx][0]      # format() 回傳 2D array：[樣本][值]
        if val < 0:
            return "."
        return str(val)
    except Exception:
        return "."
        # 【為什麼 catch 所有例外？】這裡的失敗都是「這個欄位取不到」，
        #   對結果的影響就是該欄位變成 "."。不值得讓整個 pipeline 掛掉。


def get_ad(variant, sample_idx: int) -> str:
    """
    從 FORMAT/AD 取得 allelic depth。
    回傳 "REF,ALT" 格式字串，missing 時回傳 "."

    multiallelic site 的 AD 格式為 "REF,ALT1,ALT2"，完整保留。
      ★ 雖然上游已經 norm -m -any 拆成 biallelic，
        但保留這個彈性不會有壞處。
    負數值（cyvcf2 的 missing 表示）替換為 0。
    """
    try:
        ad = variant.format("AD")
        if ad is None:
            return "."
        vals = ad[sample_idx]
        if all(v < 0 for v in vals):
            return "."               # 全部都是 missing → 整個欄位當 missing
        cleaned = [str(max(int(v), 0)) for v in vals]
        #          ↑ 部分 missing 時，把負數換成 0。
        #            理由：AD 的元素數必須與等位基因數一致，不能少寫。
        #            寫 0 表示「沒有 read 支持」，語義上最接近 missing。
        return ",".join(cleaned)
    except Exception:
        return "."


def get_vaf(variant, sample_idx: int) -> str:
    """
    從 FORMAT/VAF 取得 variant allele fraction（DV 特有欄位）。
    HC 沒有 VAF 欄位，會在 except 中回傳 "."。
      ★ 所以呼叫端只對 DV 呼叫這個函式，對 HC 不呼叫
        （呼叫也只會拿到 "."）。
    四捨五入到小數點後 4 位。
    """
    try:
        vaf = variant.format("VAF")
        if vaf is None:
            return "."
        val = vaf[sample_idx][0]
        if math.isnan(val) or val < 0:
            return "."
            #    ↑ float 的 missing 在 cyvcf2 裡是 NaN（不是負數），
            #      所以要同時檢查 isnan 與負值
        return f"{val:.4f}"
    except Exception:
        return "."


# ──────────────────────────────────────────────
# 主要處理函式
# ──────────────────────────────────────────────

def add_callers_tag(input_path: str, sample_id: str, output_path: str):
    """
    主要處理流程：
    1. 開啟輸入 VCF，確認 DV/HC sample column
    2. 在 header 新增 CALLERS、DP_DV、AD_DV、VAF_DV、DP_HC、AD_HC 定義
    3. 逐 variant 擷取值，寫出輸出 VCF
    """

    vcf_in = VCF(input_path)

    # ── 確認 sample column ────────────────────
    #   ★ 這是「快速失敗」的關鍵檢查：樣本名對不上的話，
    #     後面每一列都會出錯。與其跑到一半才死，不如開頭就明確報錯。
    expected_dv = f"{sample_id}_DV"
    expected_hc = f"{sample_id}_HC"
    samples = vcf_in.samples

    # 印出實際的樣本欄名，方便使用者對照自己傳的 --sample 是否正確
    print(f"[INFO] VCF 中的 sample columns：{samples}", file=sys.stderr)

    if expected_dv not in samples:
        print(f"[ERROR] 找不到 DV sample column：{expected_dv}", file=sys.stderr)
        sys.exit(1)
    if expected_hc not in samples:
        print(f"[ERROR] 找不到 HC sample column：{expected_hc}", file=sys.stderr)
        sys.exit(1)

    dv_idx = samples.index(expected_dv)
    hc_idx = samples.index(expected_hc)
    print(f"[INFO] DV index：{dv_idx}，HC index：{hc_idx}", file=sys.stderr)
    #  ★ 用「索引」而不是每次查名稱 —— 400 萬列 × 2 次字串查找是可觀的開銷

    # ── 新增 INFO tag 定義到 header ───────────
    #   VCF 規範要求：任何用到的 INFO 欄位都必須先在 header 宣告，
    #   否則 bcftools / VEP 會拒絕讀取或發出警告。
    new_info_fields = [
        {
            'ID': 'CALLERS',
            'Number': '1',
            'Type': 'String',
            'Description': (
                'Variant callers that detected this variant: '
                'DV+HC (both), DV (DeepVariant only), HC (HaplotypeCaller only)'
            )
        },
        {
            'ID': 'DP_DV',
            'Number': '1',
            'Type': 'String',    # 見上方「為什麼是 String」的說明
            'Description': 'Read depth from DeepVariant (FORMAT/DP). Dot if missing.'
        },
        {
            'ID': 'AD_DV',
            'Number': '1',       # ★ Number=1 而不是 R —— 因為值是「逗號分隔的字串」，
                                 #   對 VCF 而言是一個字串，不是多個數值。
                                 #   這樣就不會受 bcftools norm 的 per-allele re-size 影響
                                 #   （二級 AD 消失 bug 的教訓：Number=R 的欄位很脆弱）。
            'Type': 'String',
            'Description': (
                'Allelic depths from DeepVariant (FORMAT/AD), REF,ALT comma-separated. '
                'Dot if missing.'
            )
        },
        {
            'ID': 'VAF_DV',
            'Number': '1',
            'Type': 'String',
            'Description': (
                'Variant allele fraction from DeepVariant (FORMAT/VAF). '
                'DV-specific field. Dot if missing or HC-only variant.'
            )
        },
        {
            'ID': 'DP_HC',
            'Number': '1',
            'Type': 'String',
            'Description': 'Read depth from HaplotypeCaller (FORMAT/DP). Dot if missing.'
        },
        {
            'ID': 'AD_HC',
            'Number': '1',
            'Type': 'String',
            'Description': (
                'Allelic depths from HaplotypeCaller (FORMAT/AD), REF,ALT comma-separated. '
                'Dot if missing or DV-only variant.'
            )
        },
    ]

    for field in new_info_fields:
        vcf_in.add_info_to_header(field)
        #     ↑ 加到「輸入」的 header 物件上；Writer 會沿用它

    # ── 開啟輸出 ─────────────────────────────
    #   Writer(path, template_vcf) → 沿用 template 的 header
    vcf_out = Writer(output_path, vcf_in, mode="w")

    # ── 逐 variant 處理 ──────────────────────
    n_total = 0
    n_dv_hc = 0
    n_dv_only = 0
    n_hc_only = 0

    for variant in vcf_in:
        n_total += 1

        # CALLERS tag
        callers = determine_callers(variant, dv_idx, hc_idx)
        variant.INFO["CALLERS"] = callers

        # DV 的 DP、AD、VAF
        variant.INFO["DP_DV"]  = get_dp(variant, dv_idx)
        variant.INFO["AD_DV"]  = get_ad(variant, dv_idx)
        variant.INFO["VAF_DV"] = get_vaf(variant, dv_idx)

        # HC 的 DP、AD（HC 無 VAF 欄位）
        variant.INFO["DP_HC"] = get_dp(variant, hc_idx)
        variant.INFO["AD_HC"] = get_ad(variant, hc_idx)

        # 統計
        if callers == "DV+HC":
            n_dv_hc += 1
        elif callers == "DV":
            n_dv_only += 1
        else:
            n_hc_only += 1

        vcf_out.write_record(variant)
        # ★ 注意：輸出的 VCF 仍然有「兩個樣本欄」（沒有刪掉）。
        #   VEP 只讀 INFO 不管樣本欄，所以不影響。
        #   保留樣本欄的好處：需要時仍可回頭看原始的 FORMAT。

    vcf_out.close()
    vcf_in.close()

    # ── 統計摘要 ─────────────────────────────
    #   ★ 這四行是驗證這一步是否正常的主要依據。
    #     實測 NA12878_WES：DV+HC 約 70%、DV-only 約 6%、HC-only 約 24%。
    #     若 HC-only 突然變成 0%，就代表過濾邏輯又回到用 FILTER 了。
    print(f"[INFO] 處理完成", file=sys.stderr)
    print(f"[INFO]   總 variant 數：{n_total:,}", file=sys.stderr)
    print(f"[INFO]   DV+HC：{n_dv_hc:,} ({n_dv_hc/n_total*100:.1f}%)", file=sys.stderr)
    print(f"[INFO]   DV only：{n_dv_only:,} ({n_dv_only/n_total*100:.1f}%)", file=sys.stderr)
    print(f"[INFO]   HC only：{n_hc_only:,} ({n_hc_only/n_total*100:.1f}%)", file=sys.stderr)
    #  ⚠️ n_total 為 0 時這裡會 ZeroDivisionError。實務上不會發生
    #     （空 VCF 代表上游已經出問題了），但嚴格說應該加保護。


# ──────────────────────────────────────────────
# 命令列介面
# ──────────────────────────────────────────────

def parse_args():
    parser = argparse.ArgumentParser(
        description=(
            "在 ensemble VCF 的 INFO 欄位新增 CALLERS tag 及 DP/AD/VAF 欄位"
        ),
        formatter_class=argparse.RawDescriptionHelpFormatter,
        #                ↑ 讓 epilog 的換行與縮排原樣顯示
        epilog="""
使用範例：
  # stdin → stdout（搭配 bgzip）
  bcftools view NA12878_WES.ensemble.fixed.vcf.gz | \\
  python3 add_callers_tag.py --sample NA12878_WES | \\
  bgzip -c > snv_for_annotation.vcf.gz && \\
  tabix -p vcf snv_for_annotation.vcf.gz

  # 直接指定輸入輸出
  python3 add_callers_tag.py \\
      --input  NA12878_WES.ensemble.fixed.vcf.gz \\
      --sample NA12878_WES \\
      --output snv_for_annotation.vcf
        """
    )
    parser.add_argument("--input",  "-i", default="-",
                        help="輸入 VCF 路徑（預設：stdin）")
    #                      ↑ "-" 是 cyvcf2 的 stdin 慣例 → 支援管線用法
    parser.add_argument("--sample", "-s", required=True,
                        help="樣本 ID（例如 NA12878_WES）")
    parser.add_argument("--output", "-o", default="-",
                        help="輸出 VCF 路徑（預設：stdout）")
    return parser.parse_args()


def main():
    args = parse_args()
    # 開頭把三個參數都印出來 → log 裡永遠看得到「這次跑用了什麼輸入」
    print(f"[INFO] 輸入：{args.input}", file=sys.stderr)
    print(f"[INFO] 樣本 ID：{args.sample}", file=sys.stderr)
    print(f"[INFO] 輸出：{args.output}", file=sys.stderr)
    add_callers_tag(args.input, args.sample, args.output)


if __name__ == "__main__":
    main()
```

```groovy
/*
 * （檔頭授權與免責宣告同 main_tertiary.nf，此處省略前 35 行）
 * =========================================================
 * modules/prepare_vcf_dragen.nf
 * =============================
 * DRAGEN 路徑的前處理。與 NCKUH 路徑的三個主要差異：
 *   1. 單一樣本欄（不需要判斷 caller）
 *   2. chrM 混在主 VCF 裡 → 要分流出來
 *   3. compound 合成在這裡做（用 DRAGEN 原生 PS，不需 whatshap）
 */

// ── ADD_DRAGEN_TAG：norm → 加 INFO tag → chrM 分流 → 壓縮索引 ──
process ADD_DRAGEN_TAG {

    container "${params.sif_dir}/tertiary_python_1.0.0.sif"

    publishDir "${params.out_dir}/${sample_id}/00_prepare", mode: 'copy'

    input:
    tuple val(sample_id), path(dragen_vcf)

    // ★ 兩個 emit：SNV 與 mito 分開往下游走
    output:
    tuple val(sample_id),
          path("${sample_id}.snv_for_annotation.vcf.gz"),
          path("${sample_id}.snv_for_annotation.vcf.gz.tbi"),
          emit: snv_ch

    tuple val(sample_id),
          path("${sample_id}.mito_for_annotation.vcf.gz"),
          path("${sample_id}.mito_for_annotation.vcf.gz.tbi"),
          emit: mito_ch

    script:
    """
    # Step 1：正規化 + 拆分多等位基因（left-align + split multiallelics）
    #   讓每個 ALT 各自一列，使 AD/VAF 與後續 VEP / gnomAD / ClinVar 註解 per-allele 正確。
    #   DRAGEN VCF 多半已正規化，再跑一次為冪等、無害。
    #   -c w：REF 與參考不符時只警告不中斷。
    bcftools norm -m -any -f ${params.ref_fasta} -c w \\
        ${dragen_vcf} \\
        -Oz -o ${sample_id}.norm.vcf.gz
    tabix -p vcf ${sample_id}.norm.vcf.gz

    # Step 2：add_dragen_tag.py（吃正規化後的 biallelic VCF）
    #   - 新增 INFO tag：CALLERS, DP_DRAGEN, AD_DRAGEN, VAF_DRAGEN, GQ_DRAGEN
    #     ★ 欄位命名刻意與 NCKUH 的 *_DV / *_HC 平行，
    #       下游 parse_vep_csq.py 用同一套邏輯處理兩條路徑。
    #   - 分流：SNV（PASS，非 chrM）→ snv_raw.vcf；Mito（chrM 全部）→ mito_raw.vcf
    #     ★ 注意 chrM 是「全部」保留（不做 PASS 過濾）——
    #       粒線體的異質性變異常常被 DRAGEN 標記為非 PASS，
    #       但低頻異質性正是我們要看的東西，不能濾掉。
    python3 ${params.scripts_dir}/add_dragen_tag.py \\
        --input       ${sample_id}.norm.vcf.gz \\
        --sample      ${sample_id} \\
        --output_snv  ${sample_id}.snv_raw.vcf \\
        --output_mito ${sample_id}.mito_raw.vcf

    # Step 3：bgzip + tabix
    bgzip -c ${sample_id}.snv_raw.vcf  > ${sample_id}.snv_for_annotation.vcf.gz
    tabix -p vcf ${sample_id}.snv_for_annotation.vcf.gz

    bgzip -c ${sample_id}.mito_raw.vcf > ${sample_id}.mito_for_annotation.vcf.gz
    tabix -p vcf ${sample_id}.mito_for_annotation.vcf.gz

    # Step 4：統計
    #   兩份都印，可以確認分流是否合理（chrM 通常只有數十筆）
    echo "[ADD_DRAGEN_TAG] ${sample_id} SNV stats：" >&2
    bcftools stats ${sample_id}.snv_for_annotation.vcf.gz | grep "^SN" >&2

    echo "[ADD_DRAGEN_TAG] ${sample_id} Mito stats：" >&2
    bcftools stats ${sample_id}.mito_for_annotation.vcf.gz | grep "^SN" >&2

    # 清理暫時檔
    rm -f ${sample_id}.snv_raw.vcf ${sample_id}.mito_raw.vcf
    """
}

// ──────────────────────────────────────────────────────────────
// (選用) compound 合成：把相鄰/重疊的 cis 變異合成單一 canonical MNV
//   DRAGEN 自帶 PS（phase set），直接拿它做 combine，不需 whatshap（不同於二級 NCKUH
//   要先 whatshap）。這樣即使該版 DRAGEN 把 compound 拆開（如 SUZ12 delAAAinsTT），
//   也能在進 VEP 前合回一筆，讓 HGVS p. 正確（p.Glu723_Thr724delinsAla）。
//   combine_phased.py 與二級同一支（scripts/combine_phased.py，只用 Python 標準庫）；
//     ★ 兩個 repo 各存一份 byte-identical 的副本，md5 必須相同。
//       完整逐行註解見「二級大補帖第 7.5 節」，此處不重複。
//   在 ADD_DRAGEN_TAG 的 norm -m -any「之前」做（此時仍是 DRAGEN 原始表示、帶 PS）。
//     ★ 順序很重要：norm 會把 MNV 拆掉，所以 combine 必須在 norm 之前。
//   由 params.combine_phased 開關（預設 true）。chrM 多半無 PS，實質不受影響。
//   ⚠️ combine_py 以 staged path input 傳入（不用 ${params.scripts_dir}/… 直呼），這樣 nextflow
//      會對 script「內容」計 hash → 改了 script 後 -resume 會正確重跑，不會沿用舊快取（與二級一致）。
// ──────────────────────────────────────────────────────────────
process COMBINE_DRAGEN {

    label 'process_low'

    container "${params.sif_dir}/tertiary_python_1.0.0.sif"

    input:
    tuple val(sample_id), path(dragen_vcf)
    path combine_py        // ★ staged input（見上方 ⚠️）

    output:
    tuple val(sample_id), path("${sample_id}.dragen.combined.vcf.gz"), emit: vcf

    script:
    """
    # combine_phased.py 只用 Python 標準庫，讀 (bgzip) VCF、自帶 faidx（讀 \${ref_fasta}.fai）。
    python3 ${combine_py} \\
        --in ${dragen_vcf} \\
        --out ${sample_id}.dragen.combined.vcf \\
        --fasta ${params.ref_fasta} \\
        --max-gap ${params.combine_max_gap}      # 與二級同值（2），對齊 DRAGEN 原生設定
    # 用 bcftools 排序 + 索引（-Oz 自帶 bgzip、index -t 免 tabix）；tertiary_python 已含 bcftools。
    bcftools sort ${sample_id}.dragen.combined.vcf \\
        -Oz -o ${sample_id}.dragen.combined.vcf.gz
    bcftools index -t ${sample_id}.dragen.combined.vcf.gz
    rm -f ${sample_id}.dragen.combined.vcf
    """
}

workflow PREPARE_VCF_DRAGEN {
    take:
    dragen_ch   // tuple val(sample_id), path(dragen_vcf)（不需要 tbi）
                //   ★ 不需要 tbi：combine_phased.py 是循序讀檔（不做隨機存取），
                //     bcftools norm 也是。索引在 Step 1 之後才建。

    main:
    // 先 combine（用 DRAGEN 原生 PS）再進 norm/tag；--combine_phased false 可關閉。
    if (params.combine_phased) {
        // 以 staged path input 傳入 combine_phased.py（content-hash → -resume 會偵測 script 變更）。
        // 仍從 params.scripts_dir 取（維持三級「所有 python 腳本集中部署」慣例），只是改成 staged。
        ch_combine_py = file("${params.scripts_dir}/combine_phased.py", checkIfExists: true)
        //                                                              ↑ 檔案不存在就立刻報錯，
        //                                                                不要跑到 process 裡才發現

        ADD_DRAGEN_TAG(COMBINE_DRAGEN.out.vcf)
    } else {
        ADD_DRAGEN_TAG(dragen_ch)      // 跳過 combine，直接進 tag
    }

    emit:
    snv_ch  = ADD_DRAGEN_TAG.out.snv_ch
    mito_ch = ADD_DRAGEN_TAG.out.mito_ch
}


// ──────────────────────────────────────────────────────────────
// PLOIDY_REPORT_DRAGEN：把 DRAGEN 原生 *.ploidy.vcf.gz 整理成「與二級同一套」的 ploidy QC
```

## 3.7 `scripts/add_dragen_tag.py` 全文逐行註解

**與 `add_callers_tag.py` 的三個差異**：
1. 單一樣本欄（不需要判斷 caller，`CALLERS` 固定為 `"DRAGEN"`）
2. 多一個 `GQ_DRAGEN`（DRAGEN 有 GQ，DeepVariant 沒有）
3. **多了 chrM 分流**（DRAGEN 把 chrM 混在主 VCF 裡）

```python
#!/usr/bin/env python3
"""
（檔頭授權與免責宣告同 main_tertiary.nf，此處省略前 39 行）

add_dragen_tag.py
=================
把 DRAGEN hard-filtered VCF 的 FORMAT 欄位搬到 INFO，並分流 chrM。

DRAGEN FORMAT 欄位對照：
    FORMAT/DP  → DP_DRAGEN
    FORMAT/AD  → AD_DRAGEN
    FORMAT/AF  → VAF_DRAGEN   ★ 注意：DRAGEN 用 AF 不是 VAF（見 get_vaf）
    FORMAT/GQ  → GQ_DRAGEN（genotype quality，DRAGEN 有，DV 無）

輸出的 INFO tag：
    CALLERS     = "DRAGEN"（固定，區別於 ensemble pipeline 的 DV+HC / DV / HC）
      ★ 下游 parse_vep_csq.py 用 CALLERS 判斷資料來源，
        所以兩條路徑都必須有這個欄位（值不同）。
    DP_DRAGEN   = read depth
    AD_DRAGEN   = allelic depth（REF,ALT）
    VAF_DRAGEN  = variant allele fraction（四捨五入至小數點後 4 位）
    GQ_DRAGEN   = genotype quality

使用方式（由 prepare_vcf_dragen.nf 呼叫）：
    python3 add_dragen_tag.py \\
        --input   VAL-10.hard-filtered.vcf.gz \\
        --sample  VAL-10 \\
        --output_snv  VAL-10.snv_for_annotation.vcf \\
        --output_mito VAL-10.mito_for_annotation.vcf

    # 輸出再由 Nextflow module 用 bgzip + tabix 壓縮

依賴：
    pip install cyvcf2
"""

import argparse
import math
import sys

try:
    from cyvcf2 import VCF, Writer
except ImportError:
    print("[ERROR] 請先安裝 cyvcf2：pip install cyvcf2", file=sys.stderr)
    sys.exit(1)


# ──────────────────────────────────────────────────────────────
# FORMAT 欄位擷取輔助函式
#   （與 add_callers_tag.py 的三個函式幾乎相同，只多一個 get_gq；
#     刻意不共用成一個 module —— 兩支腳本各自獨立部署，
#     不想因為共用而產生 import 路徑的相依。）
# ──────────────────────────────────────────────────────────────

def get_dp(variant, sample_idx: int) -> str:
    """從 FORMAT/DP 取得 read depth，缺失回傳 '.'"""
    try:
        dp = variant.format("DP")
        if dp is None:
            return "."
        val = dp[sample_idx][0]
        return "." if val < 0 else str(val)
        #      ↑ cyvcf2 的 integer missing 是 INT_MIN（負數）
    except Exception:
        return "."


def get_ad(variant, sample_idx: int) -> str:
    """
    從 FORMAT/AD 取得 allelic depth。
    DRAGEN AD 格式為 Number=R（REF + 所有 ALT），
    回傳 'REF,ALT'（或 'REF,ALT1,ALT2' for multi-allelic）。
    """
    try:
        ad = variant.format("AD")
        if ad is None:
            return "."
        vals = ad[sample_idx]
        if all(v < 0 for v in vals):
            return "."
        cleaned = [str(max(int(v), 0)) for v in vals]
        return ",".join(cleaned)
    except Exception:
        return "."


def get_vaf(variant, sample_idx: int) -> str:
    """
    從 FORMAT/AF 取得 variant allele fraction。
    DRAGEN 用 AF（Number=A，per ALT allele），不是 VAF。
      ★★ 這是一個容易踩的坑：不同 caller 用不同的欄位名表示同一件事。
         DeepVariant 用 FORMAT/VAF，DRAGEN 用 FORMAT/AF。
         而且 AF 這個名字在 INFO 欄位裡通常是指「族群頻率」，
         在 FORMAT 欄位裡卻是指「這個樣本的等位基因比例」——
         同名不同義，讀 VCF 時要特別小心。
    multi-allelic 時取第一個 ALT 的值（主要 ALT）。
      ★ 上游已 norm -m -any 拆成 biallelic，所以實際上只有一個 ALT。
    """
    try:
        af = variant.format("AF")
        if af is None:
            return "."
        val = af[sample_idx][0]
        if math.isnan(val) or val < 0:
            return "."
        return f"{val:.4f}"
    except Exception:
        return "."


def get_gq(variant, sample_idx: int) -> str:
    """從 FORMAT/GQ 取得 genotype quality，缺失回傳 '.'
    ★ GQ = Phred-scaled 的「這個基因型判斷有多可信」。
      GQ 20 = 99% 信心，GQ 30 = 99.9%。臨床判讀常用 GQ ≥ 20 當門檻。
      DeepVariant 的 ensemble 路徑沒有這個欄位（DV 用不同的品質表示法）。"""
    try:
        gq = variant.format("GQ")
        if gq is None:
            return "."
        val = gq[sample_idx][0]
        return "." if val < 0 else str(val)
    except Exception:
        return "."


# ──────────────────────────────────────────────────────────────
# 主要處理函式
# ──────────────────────────────────────────────────────────────

def add_dragen_tag(
    input_path: str,
    sample_id: str,
    output_snv_path: str,
    output_mito_path: str,
):
    """
    主要處理流程：
    1. 開啟 DRAGEN hard-filtered VCF（單一 sample column）
    2. 新增 INFO tag：CALLERS, DP_DRAGEN, AD_DRAGEN, VAF_DRAGEN, GQ_DRAGEN
    3. 分流：
       - chrM → mito VCF（保留所有 FILTER，包含 non-PASS）
       - 非 chrM + FILTER=PASS → snv VCF
    4. 輸出兩個未壓縮 VCF（由 Nextflow 後續 bgzip + tabix）
    """

    vcf_in = VCF(input_path)

    # ── 確認 sample column ────────────────────────────────────
    samples = vcf_in.samples
    print(f"[INFO] VCF 中的 sample column：{samples}", file=sys.stderr)

    if sample_id not in samples:
        print(f"[ERROR] 找不到 sample：{sample_id}", file=sys.stderr)
        print(f"  VCF 中的 sample：{samples}", file=sys.stderr)
        sys.exit(1)
        # ★ 這個檢查對 DRAGEN 特別重要：DRAGEN 的樣本名來自 run 設定，
        #   可能與 sample sheet 填的 sample_id 不同（例如多了前綴）。
        #   把 VCF 裡的實際樣本名印出來，使用者一看就知道要怎麼改。

    sample_idx = samples.index(sample_id)
    print(f"[INFO] sample index：{sample_idx}", file=sys.stderr)

    # ── 新增 INFO tag 定義到 header ───────────────────────────
    #   （Number=1 / Type=String 的理由同 add_callers_tag.py：
    #     避免被 bcftools 的 per-allele re-size 影響，且能表示 "."）
    new_info_fields = [
        {
            'ID': 'CALLERS',
            'Number': '1',
            'Type': 'String',
            'Description': (
                'Variant caller: DRAGEN (single caller, no ensemble)'
            )
        },
        {
            'ID': 'DP_DRAGEN',
            'Number': '1',
            'Type': 'String',
            'Description': 'Read depth from DRAGEN (FORMAT/DP). Dot if missing.'
        },
        {
            'ID': 'AD_DRAGEN',
            'Number': '1',
            'Type': 'String',
            'Description': (
                'Allelic depths from DRAGEN (FORMAT/AD), REF,ALT comma-separated. '
                'Dot if missing.'
            )
        },
        {
            'ID': 'VAF_DRAGEN',
            'Number': '1',
            'Type': 'String',
            'Description': (
                'Variant allele fraction from DRAGEN (FORMAT/AF). '
                'Rounded to 4 decimal places. Dot if missing.'
            )
        },
        {
            'ID': 'GQ_DRAGEN',
            'Number': '1',
            'Type': 'String',
            'Description': (
                'Genotype quality from DRAGEN (FORMAT/GQ). '
                'Dot if missing.'
            )
        },
    ]

    for field in new_info_fields:
        vcf_in.add_info_to_header(field)

    # ── 開啟兩個輸出 VCF ─────────────────────────────────────
    #   兩個 Writer 共用同一份 header（都從 vcf_in 複製）
    vcf_snv  = Writer(output_snv_path,  vcf_in, mode="w")
    vcf_mito = Writer(output_mito_path, vcf_in, mode="w")

    # ── 逐 variant 處理 ──────────────────────────────────────
    n_total    = 0
    n_snv_pass = 0
    n_mito     = 0
    n_filtered = 0   # 非 chrM 且非 PASS（直接丟棄）

    for variant in vcf_in:
        n_total += 1

        chrom = variant.CHROM

        # 新增 INFO tag（所有 variant 都加，不論要輸出到哪）
        #   ★ 先加 tag 再分流，兩邊的輸出格式才會一致
        variant.INFO["CALLERS"]    = "DRAGEN"
        variant.INFO["DP_DRAGEN"]  = get_dp(variant, sample_idx)
        variant.INFO["AD_DRAGEN"]  = get_ad(variant, sample_idx)
        variant.INFO["VAF_DRAGEN"] = get_vaf(variant, sample_idx)
        variant.INFO["GQ_DRAGEN"]  = get_gq(variant, sample_idx)

        # ── 分流邏輯 ─────────────────────────────────────────
        if chrom == "chrM" or chrom == "MT":
            # Mito：全部保留（包含 non-PASS），供 Mito module 使用
            #
            # ★★ 這是刻意的設計，不是漏寫過濾 ★★
            #   粒線體變異的臨床意義常在「低頻異質性」（heteroplasmy 5–20%）。
            #   DRAGEN 的 germline hard filter 是為二倍體核基因體設計的，
            #   會把低 VAF 的變異標成非 PASS。若照套用，正是最重要的
            #   異質性變異會被全部丟掉。
            #   所以 chrM 全部保留，過濾交給 MITO_ANNOTATE 用粒線體專屬邏輯判斷。
            vcf_mito.write_record(variant)
            n_mito += 1

        else:
            # 非 Mito：只保留 PASS
            # DRAGEN FILTER 欄位可能有多個值（如 LowDepth;PloidyConflict）
            # cyvcf2 的 variant.FILTER 回傳 None 或 list
            #
            # 【cyvcf2 的 FILTER 語義】
            #   FILTER=PASS  → variant.FILTER 回傳 None（!）
            #   FILTER=.     → 也可能是 None 或空
            #   FILTER=xxx   → 回傳字串 "xxx" 或 list
            #   ★ 「PASS 回傳 None」很反直覺，所以下面的判斷寫得很囉唆 ——
            #     四種情況都當成 PASS，寧可寬鬆也不要誤丟。
            filters = variant.FILTER
            is_pass = (filters is None or filters == "PASS" or filters == [] or
                      (isinstance(filters, str) and filters == "PASS"))

            if is_pass:
                vcf_snv.write_record(variant)
                n_snv_pass += 1
            else:
                n_filtered += 1

        # 進度回報：每 50 萬列印一次
        #   ★ WGS 有 400–500 萬列，跑幾分鐘。沒有進度回報的話
        #     使用者會以為卡住了。
        if n_total % 500_000 == 0:
            print(
                f"[INFO] 已處理 {n_total:,}（SNV PASS: {n_snv_pass:,}，"
                f"Mito: {n_mito:,}，已過濾: {n_filtered:,}）",
                file=sys.stderr
            )

    vcf_snv.close()
    vcf_mito.close()
    vcf_in.close()

    # ── 統計摘要 ─────────────────────────────────────────────
    #   ★ 這四行是驗證分流是否正確的依據：
    #     - chrM 數量應該是數十到數百（不會是 0，也不會上萬）
    #     - 非 PASS 丟棄的比例通常 10–20%
    #     ★ 這裡就是當初確認「AD 消失 bug」的地方：
    #       總數 5,940,563 → SNV PASS 5,940,465，數字合理，
    #       所以問題不在分流而在 combine（見二級大補帖 7.6）。
    print(f"\n[INFO] 處理完成", file=sys.stderr)
    print(f"[INFO]   總 variant 數 ：{n_total:>10,}", file=sys.stderr)
    print(f"[INFO]   SNV/indel PASS：{n_snv_pass:>10,}  → {output_snv_path}", file=sys.stderr)
    print(f"[INFO]   chrM（全部）  ：{n_mito:>10,}  → {output_mito_path}", file=sys.stderr)
    print(f"[INFO]   非 PASS 丟棄  ：{n_filtered:>10,}", file=sys.stderr)


# ──────────────────────────────────────────────────────────────
# 命令列介面
# ──────────────────────────────────────────────────────────────

def parse_args():
    parser = argparse.ArgumentParser(
        description=(
            "DRAGEN VCF 前處理：新增 CALLERS/DP/AD/VAF tag，"
            "並分流為 SNV（PASS）和 Mito 兩個輸出"
        ),
        formatter_class=argparse.RawDescriptionHelpFormatter,
        epilog="""
使用範例：
  python3 add_dragen_tag.py \\
      --input   VAL-10.hard-filtered.vcf.gz \\
      --sample  VAL-10 \\
      --output_snv  VAL-10.snv_for_annotation.vcf \\
      --output_mito VAL-10.mito_for_annotation.vcf
        """
    )
    parser.add_argument("--input",       "-i", required=True,
                        help="DRAGEN hard-filtered VCF（.vcf.gz 或 .vcf）")
    parser.add_argument("--sample",      "-s", required=True,
                        help="Sample ID（VCF 中的 sample column 名稱，例如 VAL-10）")
    parser.add_argument("--output_snv",  required=True,
                        help="輸出 SNV/indel VCF（PASS，非 chrM）")
    parser.add_argument("--output_mito", required=True,
                        help="輸出 Mito VCF（chrM 全部，含 non-PASS）")
    return parser.parse_args()


def main():
    args = parse_args()
    print(f"[INFO] 輸入：{args.input}", file=sys.stderr)
    print(f"[INFO] Sample ID：{args.sample}", file=sys.stderr)
    print(f"[INFO] 輸出 SNV：{args.output_snv}", file=sys.stderr)
    print(f"[INFO] 輸出 Mito：{args.output_mito}", file=sys.stderr)
    add_dragen_tag(args.input, args.sample, args.output_snv, args.output_mito)


if __name__ == "__main__":
    main()
```

## 3.8 `scripts/parse_dragen_ploidy.py` 全文逐行註解

### ⚠️ 兩條路徑的 NDC 語義不同 —— 這是刻意的

| | 二級 `ploidy_check.py` | 三級 `parse_dragen_ploidy.py`（DRAGEN 原生） |
|---|---|---|
| NDC 定義 | 相對體染色體中位數的**原始**覆蓋比 | 觀測 ÷「**估計核型下的期望**」（已對性別正規化） |
| 正常男性 chrX | NDC ≈ **0.5** | NDC ≈ **1.0** |
| 用途 | 用來**推**性別 | 性別已由 DRAGEN 給出，NDC 只用來抓非整倍體 |
| 非整倍體判定 | NDC 偏離 1.0（先用 RATIO 推核型再正規化） | NDC 直接偏離 1.0 |

**注意**：二級也輸出一個 `RATIO` 欄位（= 原始覆蓋比，男性 chrX ≈ 0.5），
而二級的 `NDC` 是「正規化後」的（≈ 1.0）—— 所以**兩份 QC 的 NDC 語義其實是一致的**，
都是「≈1.0 代表符合預期」。差別只在二級要自己推核型，DRAGEN 直接給。

**結果**：兩份 `ploidy_qc.txt` 的 `核型 / sex_check / WARNINGS` 語義完全一致，
判讀者不需要學兩套。

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
=========================================================
WGS/WES Germline Analysis Pipeline - parse_dragen_ploidy.py
=========================================================
Author   : Po-Yu Lin (林伯昱)
（機構/聯絡/GPL-3.0/免責宣告同前）
=========================================================
scripts/parse_dragen_ploidy.py
==============================

讀 DRAGEN 原生 `*.ploidy.vcf.gz`，輸出「與二級 ploidy_check.py 同一套」的 QC 摘要
（<sample>.ploidy_qc.txt），讓 NCKUH 與 DRAGEN 兩條路的 ploidy 呈現一致。warn-only。

⚠️ DRAGEN 的 NDC 語意（實測 chrX 男性 = 1.0 而非 0.5）：
  NDC = 觀測深度 ÷「估計核型下的期望深度」，已對**性別**正規化。所以：
    - 正常樣本每條 contig（含 chrX/chrY）NDC ≈ 1.0。
    - 偏離 1.0 = 非預期（如體染色體三體 ≈1.5；或估計核型與實際不符）。
  故 aneuploidy 判定 = 「NDC 偏離 1.0」（只信 FILTER=PASS 的 contig；chrM 多拷貝跳過）。
  性別直接取 ##estimatedSexKaryotype；與 ##referenceSexKaryotype 不符 → WARN。
    ★ 「實測 chrX 男性 = 1.0 而非 0.5」這句是實際看資料驗證出來的，
      不是從文件推的。這種「先看資料再寫程式」的做法值得堅持 ——
      DRAGEN 的文件對 NDC 的定義寫得並不清楚。

（對照：二級 ploidy_check.py 的 NDC = 相對體染色體中位數的**原始**覆蓋比，男性 chrX ≈ 0.5，
  用來「推」性別；兩者 NDC 數字尺度不同，但 qc.txt 的核型/sex_check/WARNINGS 語意一致。）
  ★ 這段對照註解略舊：二級後來也改成「NDC 正規化、另存 RATIO 原始比」，
    所以現在兩者的 NDC 尺度其實是一致的（都 ≈1.0）。見上方 3.8 的表格。

相依：只用 Python 標準庫。
"""

import argparse
import gzip
import sys

AUTOSOMES = ["chr%d" % i for i in range(1, 23)]
MITO = {"chrM", "chrMT", "MT", "M"}
NDC_LO, NDC_HI = 0.75, 1.25   # NDC 偏離此區間（PASS contig）→ 疑似非整倍體
                              #   ★ 與二級的 ANEUPLOIDY_LO/HI 相同（±0.25），
                              #     兩條路徑的判定閾值一致。


def _open(path):
    """自動判斷 gzip（看 magic number），與 combine_phased.py 同一個技巧。"""
    with open(path, "rb") as fh:
        magic = fh.read(2)
    return gzip.open(path, "rt") if magic == b"\x1f\x8b" else open(path, "rt")


def _f(x):
    """安全的 float 轉換：轉不動就回 None（而不是拋例外）。"""
    try:
        return float(x)
    except (TypeError, ValueError):
        return None


def parse(path):
    """回傳 (estimated, reference, contigs)；contigs = [(chrom, filt, dc, ndc), ...]。"""
    est = ref = None
    contigs = []
    with _open(path) as f:
        for line in f:
            if line.startswith("##"):
                # 從 header 的 meta 行取核型
                #   ★ 這兩個 key 就是二級 ploidy_check.py 刻意沿用的名稱，
                #     兩份 VCF 才能用同一個方式解析。
                if line.startswith("##estimatedSexKaryotype="):
                    est = line.strip().split("=", 1)[1]
                elif line.startswith("##referenceSexKaryotype="):
                    ref = line.strip().split("=", 1)[1]
                continue
            if line.startswith("#"):
                continue                      # #CHROM 那一行
            p = line.rstrip("\n").split("\t")
            if len(p) < 10:
                continue                      # 沒有樣本欄的殘缺行
            chrom, filt, fmt, smp = p[0], p[6], p[8], p[9]
            #                        ↑CHROM  ↑FILTER ↑FORMAT ↑樣本
            d = dict(zip(fmt.split(":"), smp.split(":")))
            #   把 "DC:NDC" + "31.5:1.02" 配成 {"DC": "31.5", "NDC": "1.02"}
            contigs.append((chrom, filt, _f(d.get("DC")), _f(d.get("NDC"))))
    return est, ref, contigs


def analyze(est, ref, contigs):
    """判定 + 產生警告清單。純函式，好測試。"""
    warnings = []
    # 警告 1：性別不符
    #   ★ DRAGEN 自己就會比對 estimated 與 reference，但它只寫在 header 裡，
    #     不會主動提醒。這裡把它變成明確的 WARN。
    if est and ref and est != ref:
        warnings.append("SEX MISMATCH：DRAGEN estimated %s vs reference %s"
                        "（可能 sample swap 或性染色體 aneuploidy，請人工確認）" % (est, ref))
    flags = []
    for chrom, filt, dc, ndc in contigs:
        if ndc is None or chrom in MITO:
            continue                          # chrM 多拷貝，NDC 無意義（同二級）
        if filt not in ("PASS", ".", ""):     # 只信 PASS（如 chr19 常見 LowQual → 不判）
            continue
            # ★ 【為什麼 chr19 常見 LowQual？】chr19 的 GC 含量特別高（約 48%），
            #   PCR 效率與定序品質都較差，DRAGEN 常把它的 ploidy 判定標成低品質。
            #   對這種 contig 硬判非整倍體只會產生假警報。
        if ndc < NDC_LO or ndc > NDC_HI:
            flags.append((chrom, ndc))
            warnings.append("%s NDC=%.2f → 疑似非整倍體（DRAGEN NDC 已對估計核型正規化，"
                            "偏離 1.0 = 非預期）；本染色體 SNV 基因型可能不準，考慮人工確認"
                            % (chrom, ndc))
            #  ★ 警告文字裡明確說明「NDC 已正規化」，
            #    避免判讀者拿 DRAGEN 的 NDC 去對二級的 RATIO 而困惑。
    return {
        "estimated": est or "unknown",
        "reference": ref or "unknown",
        "contigs": contigs,
        "aneuploidy": flags,
        "warnings": warnings,
    }


def write_qc(path, sample, res):
    """輸出與二級同格式的 QC 摘要。"""
    order = AUTOSOMES + ["chrX", "chrY", "chrM"]
    ndc_by = {c: ndc for (c, filt, dc, ndc) in res["contigs"]}
    # sex_check 的三種 OK 情況（與二級完全相同的邏輯）
    sex_ok = (res["estimated"] in ("unknown",) or res["reference"] in ("unknown",)
              or res["estimated"] == res["reference"])
    with open(path, "w") as w:
        # ★ 前四行的欄位名稱與二級 ploidy_qc.txt 完全一致，
        #   只有 (DRAGEN) 標記與 source 那行不同。
        w.write("# Ploidy QC — %s (DRAGEN)\n" % sample)
        w.write("declared_sex_karyotype : %s\n" % res["reference"])
        w.write("estimated_sex_karyotype: %s\n" % res["estimated"])
        w.write("sex_check              : %s\n" % ("OK" if sex_ok else "MISMATCH"))
        w.write("source                 : DRAGEN native ploidy.vcf "
                "(NDC normalized to expected karyotype; ~1.0 = as-expected)\n")
        #        ↑ 明確標示來源與 NDC 語義，判讀者一看就知道這份是 DRAGEN 算的
        w.write("\n--- per-chromosome normalized coverage (NDC) ---\n")
        # 先列主要 contig（依 order），再列其他（DRAGEN 有時會多出 decoy）
        listed = [c for c in order if c in ndc_by] + \
                 [c for c in ndc_by if c not in order]
        #  ★ 與二級不同：二級是「只列主要 contig」，這裡是「主要的排前面，
        #    其他的仍然列出」。因為 DRAGEN 的 ploidy.vcf 本來就只含少數 contig，
        #    不像 mosdepth 會吐 3000 多個。
        for c in listed:
            v = ndc_by[c]
            w.write("%-6s %s\n" % (c, ("%.3f" % v) if v is not None else "NA"))
        w.write("\n--- WARNINGS ---\n")
        if res["warnings"]:
            for msg in res["warnings"]:
                w.write("WARN: %s\n" % msg)
        else:
            w.write("(none)\n")


def main():
    ap = argparse.ArgumentParser(description="Summarize DRAGEN ploidy.vcf into unified QC txt.")
    ap.add_argument("--in", dest="inp", required=True, help="DRAGEN *.ploidy.vcf(.gz)")
    ap.add_argument("--sample", required=True)
    ap.add_argument("--out-qc", required=True)
    a = ap.parse_args()
    est, ref, contigs = parse(a.inp)
    res = analyze(est, ref, contigs)
    write_qc(a.out_qc, a.sample, res)
    # 警告同時進 stderr → .command.err，跑完整批可以 grep 找出有問題的樣本
    for msg in res["warnings"]:
        sys.stderr.write("[parse_dragen_ploidy] WARN: %s\n" % msg)
    sys.stderr.write("[parse_dragen_ploidy] %s estimated=%s reference=%s aneuploidy=%d\n"
                     % (a.sample, res["estimated"], res["reference"], len(res["aneuploidy"])))
    # ★ 全程沒有非零 exit —— warn-only 的承諾（與二級一致）


if __name__ == "__main__":
    main()
```

## 4.3 ⚠️ 為什麼用 Pangolin 而不是 SpliceAI

**SpliceAI 商業使用需付費授權**（Illumina）。
**Pangolin 是 GPL-3.0**，可商用，準確度相當（部分基準測試略優）。

這是本 pipeline 第三個「因授權而換工具」的實例
（前兩個：Manta→Delly、MITOMAP→gnomAD-mito）。

## 4.4 ⚠️ 為什麼用 `--flag_pick` 而不是 `--pick`

| | `--pick` | `--flag_pick` |
|---|---|---|
| 行為 | **只輸出一個** transcript | 輸出**全部** transcript，代表的那個標記 `PICK=1` |
| 問題 | MANE Plus Clinical 的第二個轉錄本會被丟掉 | 無 |
| 下游 | 無法回頭看其他轉錄本 | `parse_vep_csq.py` 可自行選、也可展開全部 |

臨床判讀常需要看「這個變異在另一個轉錄本上是什麼後果」，
所以**保留全部**，由 `parse_vep_csq.py` 決定要呈現哪一個。

**`--pick_order` 的優先序**：
```
mane_select > mane_plus_clinical > canonical > appris > tsl > biotype > ccds > rank > length
```
MANE Select 是 NCBI 與 EMBL-EBI 共同認定的「每個基因一個代表轉錄本」，
臨床報告的標準。放在第一優先。

## 4.5 ⚠️ CSQ 欄位位置不能寫死

VEP 的 `CSQ` 是 pipe 分隔的字串，欄位數量**隨旗標而變**。
加了 `--hgvs`/`--symbol`/`--numbers` 之後，`PICK` 就不再是第 22 欄。

**正確做法**：從 VCF header 的
`##INFO=<ID=CSQ,...,Format="Allele|Consequence|IMPACT|...">`
那一行**動態解析**欄位位置。`parse_vep_csq.py` 就是這樣做的（見第 5 章）。

寫死欄位位置的話，任何人加一個 VEP 旗標，所有欄位就會**整批錯位**
—— 而且不會報錯，只是資料全部對到錯的欄位。

## 4.6 `modules/snv_annotation.nf` 全文逐行註解

```groovy
/*
 * （檔頭授權與免責宣告同 main_tertiary.nf，此處省略前 29 行）
 * =========================================================
 * modules/snv_annotation.nf
 * =========================
 *   Process 1 - VEP_ANNOTATE：
 *     執行 Ensembl VEP 115，帶入以下 plugins 和 custom annotation：
 *       - dbNSFP 4.9c（BayesDel、AlphaMissense、ESM1b 等）
 *       - LOFTEE GRCh38（LoF HC/LC 判定，PVS1 基礎）
 *         * loftee 資料目錄透過 --bind 掛載至 /opt/vep/Plugins/loftee_data
 *         * gerp BigWig 透過 --bind 直接掛載至 /opt/vep/Plugins/（LOFTEE bug workaround）
 *       - LoFtool（基因 LoF 容忍度）
 *       - ClinVar 20260418（CLNSIG、CLNREVSTAT、CLNDN、CLNSIGCONF）
 *         ⚠️ 註解的日期已過時，config 目前用 clinvar_20260720
 *       - gnomAD（VEP cache 內建，--af_gnomadg + --af_gnomade）
 *       - 1000 Genomes（VEP cache 內建，--af_1kg，提供 EAS_AF 等次族群頻率）
 *
 *     annotation 旗標（CSQ 欄位內容）：
 *       ★ 每一個旗標都有明確的下游用途，不是「開越多越好」——
 *         每多一個旗標，CSQ 就多一欄，WGS 的 VCF 會大幾百 MB。
 *       - --hgvs    ：輸出 HGVSc / HGVSp（TSV 主表必要欄位，無此旗標欄位為空）
 *       - --symbol  ：輸出 HGNC gene symbol（GENE 欄位，無此旗標只有 Ensembl ID）
 *       - --numbers ：輸出 EXON / INTRON 編號（格式 2/15，PVS1 NMD escape 判斷需要）
 *       - --canonical：輸出 CANONICAL 旗標（transcript 備用選取依據）
 *       - --biotype ：輸出 BIOTYPE（PVS1 需確認 protein_coding）
 *       - --tsl     ：輸出 TSL（--pick_order 的 tsl 層才有資料可比較）
 *       - --appris  ：輸出 APPRIS（--pick_order 的 appris 層才有資料可比較）
 *         ★ 上面兩個很重要：--pick_order 裡列了 appris/tsl，
 *           但若沒開對應旗標，那兩層就沒有資料可比 → 排序會直接跳過它們。
 *       - --uniprot ：輸出 SWISSPROT / TREMBL（PM1 UniProt domain 判斷依據）
 *       - --domains ：輸出 DOMAINS（PM1 蛋白質 domain 資訊）
 *       - --safe    ：plugin 報錯時 VEP 正確退出（臨床 pipeline 必要）
 *         ★★ --safe 是臨床 pipeline 的關鍵旗標：不加的話，plugin 出錯時
 *            VEP 會「跳過該筆繼續跑」並以 exit 0 結束 —— 你會拿到一份
 *            看起來正常、但某些變異缺少註解的 VCF，而且完全不知道。
 *            加了 --safe，plugin 出錯就整個 VEP 失敗，Nextflow 才會告訴你。
 *
 *     transcript 策略：
 *       - --mane：標記 MANE Select / MANE Plus Clinical
 *       - --flag_pick：標記代表 transcript（PICK 欄位值為 1）
 *       - --pick_order：mane_select > mane_plus_clinical > canonical > appris > tsl > ...
 *       - 注意：不用 --pick（--pick 只保留一個 transcript，無法展開所有 MANE）
 *               只用 --flag_pick，保留所有 transcript，以 PICK=1 標記代表 transcript
 *     PICK 欄位說明：
 *       VCF 的 CSQ 欄位中，PICK 是第 22 個 pipe-separated 值（從 1 開始數）
 *       值為 "1" 表示此 transcript 是代表 transcript，值為空表示非代表
 *       加入 --hgvs/--symbol 等旗標後，PICK 的欄位位置會往後移，
 *       parse_vep_csq.py 應從 VCF header 的 CSQ 欄位定義動態解析位置，不要硬編碼
 *       ★★ 這段就是 4.5 說的那個坑 ★★
 *
 *   Process 2 - PANGOLIN_SCORE：
 *     對 VEP 輸出中帶有 splice consequence 的 variant 執行 Pangolin inference。
 *     取代 SpliceAI（SpliceAI 商用需付費授權，Pangolin 為 GPL-3.0）。
 *     GPU inference（--nv 由 config 的 process_gpu label containerOptions 設定）。
 *
 * 輸入：
 *   tuple val(sample_id), path(snv_vcf), path(snv_tbi)
 *
 * 輸出：
 *   vep_ch:      tuple val(sample_id), path("*.vep.vcf.gz"), path("*.vep.vcf.gz.tbi")
 *   pangolin_ch: tuple val(sample_id), path("*.pangolin.vcf.gz"), path("*.pangolin.vcf.gz.tbi")
 *
 * 已知踩雷：
 *   ★★ 這一段是整個檔案最有價值的內容 —— 四個實際踩過的坑 ★★
 *   - --stats_file 和 --no_stats 不能同時使用，本 module 統一用 --no_stats（較快）
 *   - LOFTEE gerp_dist.pl bug：路徑拼接缺少 /，需要透過 --bind 直接掛載 gerp bw
 *   - tabix 必須在 VEP 輸出之後才能建 index（VEP 加 --compress_output bgzip 自動壓縮）
 *   - 加入 --hgvs/--symbol/--numbers 等旗標後，CSQ 欄位的 column 數增加，
 *     PICK 的欄位位置不再是固定第 22 欄，parse_vep_csq.py 必須從 VCF header
 *     動態解析 CSQ format（##INFO=<ID=CSQ,...,Format="..."> 那行）
 */

    //                 （含 human_ancestor.fa.gz、loftee.sql、gerp_...GRCh38.bw）

    //

    tuple val(sample_id), path(snv_vcf), path(snv_tbi)

    tuple val(sample_id),
          path("${sample_id}.vep.vcf.gz"),
          path("${sample_id}.vep.vcf.gz.tbi"),
          emit: vep_out

    script:
    // ── dbNSFP 版本切換（--academic_dbnsfp，預設 false）──────────────────────
    //   false → dbNSFP 4.9c（預設路徑，維持全部工具可商用）
    //   true  → dbNSFP 5.3a，並額外抓 REVEL / MutPred2 / VEST4 / CADD_phred
    //           ★ 這些多為「學術免費、商業需另行授權」（CADD 尤其明確），故只在此模式取用。
    //   兩版都已把 P-KNN 合併進去（PKNN_LLR 為最後一欄），GUI 排序訊號不受影響；
    //     ★ P-KNN 是本院自建的預測分數，是 GUI 排序最重要的訊號。
    //       兩個版本的 dbNSFP 都必須 merge 進去，否則換版會讓排序失效。
    //   5.3a 的 P-KNN 覆蓋更完整（P-KNN 本來就是以 dbNSFP 5.3 產生）。
    //   族群頻率欄名在 5.3a 改了：gnomAD_exomes_* → gnomAD4.1_joint_*（gnomAD 4.1，
    //   exomes+genomes 合併），parse_vep_csq.py 以 get_any() 相容兩種欄名。
    // ⚠️ 不要用 `as boolean`：Groovy 對非空字串一律為 true，指令列傳 "--academic_dbnsfp false"
    //    會被誤判成開啟。一律轉小寫字串比對。
    def academic   = params.academic_dbnsfp.toString().toLowerCase() == 'true'
    def dbnsfp_f   = academic ? params.dbnsfp_academic : params.dbnsfp

    // ★★★ 這是換 dbNSFP 版本時最重要的設計決定 ★★★
    // ACMG 用的族群頻率：兩版都取 gnomAD 2.1.1 exomes，讓 PM2 的判讀基準不因換版而變。
    //   4.9c 有「整體」欄位；5.3a 只保留 controls / non_neuro / non_cancer 三個子集，
    //   取 non_cancer（約 118k，最接近整體的 ~125k；controls 僅約 60k 差距過大）。
    //
    // 【為什麼堅持用同一版 gnomAD？】
    //   換 dbNSFP 的目的是「換 in-silico 預測工具」（PP3/BP4），
    //   不是換族群頻率（PM2/BA1/BS1）。若順便換成 gnomAD 4.1（800k 個體），
    //   同一個變異的 AF 會改變 → PM2 的判定跟著改 → 整個 ACMG 分類都不同。
    //   那就無法回答「換版本後結果為什麼變了」這個問題。
    //   所以：ACMG 基礎不動，新工具與新頻率一律另開「參考欄位」。
    def dbnsfp_af  = academic
        ? "gnomAD2.1.1_exomes_non_cancer_AF,gnomAD2.1.1_exomes_non_cancer_EAS_AF"
        : "gnomAD_exomes_AF,gnomAD_exomes_EAS_AF"
    // 5.3a 額外抓的「參考用」欄位（不進 ACMG 計分）：新 in-silico 工具 + gnomAD 4.1。
    def dbnsfp_extra = academic
        ? ",REVEL_score,MutPred2_score,MutPred2_pred,VEST4_score,CADD_phred" +
          ",gnomAD4.1_joint_AF,gnomAD4.1_joint_EAS_AF"
        : ""
    """
    # 把實際使用的 dbNSFP 印進 log（與 banner 呼應，雙重追溯）
    echo "[VEP_ANNOTATE] dbNSFP = ${dbnsfp_f}" >&2

    vep \\
        --input_file ${snv_vcf} \\
        --output_file ${sample_id}.vep.vcf.gz \\
        --vcf \\                                  # 輸出 VCF 格式（不是 VEP 預設的 tab 格式）
        --compress_output bgzip \\                # 直接輸出 bgzip（省一步）
        \\
        --offline \\                              # 完全離線，不連 Ensembl 伺服器
                                                  #   ★ 臨床必要：結果不能依賴外部服務的可用性，
                                                  #     也不能把病人的變異送到外部
        --cache \\                                # 用本地 cache
        --dir_cache ${params.vep_cache} \\
        --dir_plugins /opt/vep/Plugins \\
        --assembly GRCh38 \\
        --fasta ${params.ref_fasta} \\            # HGVS 計算需要參考序列
        --fork ${task.cpus} \\                    # 平行處理（VEP 的平行度）
        \\
        # ---- CSQ 內容旗標（每個的用途見檔頭註解）----
        --hgvs \\
        --symbol \\
        --numbers \\
        --total_length \\                         # 讓 Protein_position 變成 "pos/total" 格式
                                                  #   ★ PVS1 決策樹要算「截斷掉多少比例的蛋白質」，
                                                  #     需要知道蛋白質總長度。加了這個旗標，
                                                  #     Protein_position 會是 "723/739"，
                                                  #     acmg_classifier.py 直接就能算出比例。
        --canonical \\
        --biotype \\
        --tsl \\
        --appris \\
        --uniprot \\
        --domains \\
        \\
        # ---- transcript 選取策略 ----
        --mane \\
        --flag_pick \\
        --pick_order mane_select,mane_plus_clinical,canonical,appris,tsl,biotype,ccds,rank,length \\
        \\
        # ---- Plugin 1：dbNSFP（最大的一個，提供所有 in-silico 分數）----
        #   格式：--plugin dbNSFP,<檔案>,<欄位1>,<欄位2>,...
        #   ★ 下面的反斜線換行是為了可讀性；bash 會把它們接成一行
        --plugin dbNSFP,${dbnsfp_f},\\
BayesDel_noAF_score,BayesDel_noAF_pred,\\
    # ↑ BayesDel：整合多種證據的貝氏刪除性分數。noAF 版不含族群頻率
    #   （避免與 PM2 重複計算同一個證據）—— 這是刻意選 noAF 而非含 AF 版的理由。
AlphaMissense_score,AlphaMissense_pred,\\
    # ↑ DeepMind 的錯義變異致病性預測，2023 發表，目前最準的錯義預測之一
ESM1b_score,ESM1b_pred,\\
    # ↑ Meta 的蛋白質語言模型，不依賴多序列比對（對缺乏同源序列的基因較有優勢）
VARITY_R_score,\\
    # ↑ 針對「罕見變異」訓練的模型（多數工具在罕見變異上表現較差）
SIFT_score,SIFT_pred,\\
    # ↑ 經典的保守性方法，保留它是為了與舊報告可比對
DANN_score,\\
    # ↑ 深度神經網路版的 CADD
PHACTboost_score,\\
    # ↑ 系統發育感知的方法
phyloP100way_vertebrate,\\
    # ↑ 100 種脊椎動物的位點保守性
GERP++_RS,\\
    # ↑ 另一種保守性度量（拒絕替換分數）
${dbnsfp_af},\\
    # ↑ 族群頻率（見上方的版本切換邏輯）
PKNN_LLR${dbnsfp_extra} \\
    # ↑ 本院自建的 P-KNN 對數似然比；${dbnsfp_extra} 只在 academic 模式下有內容
        \\
        # ---- Plugin 2：LOFTEE（PVS1 的基礎）----
        #   把 LoF 變異分成 HC（高信心）與 LC（低信心）。
        #   LC 的常見原因：位於最後一個 exon、影響的轉錄本非主要、
        #   附近有 rescue 剪接位點、位於低保守性區域…
        #   ★ PVS1 只能用在 HC 上；LC 要降級或不用。
        --plugin LoF,\\
loftee_path:/opt/vep/Plugins/,\\
human_ancestor_fa:/opt/vep/Plugins/loftee_data/human_ancestor.fa.gz,\\
    # ↑ 人類祖先序列：判斷「這個 stop codon 是不是祖先型」
    #   （若祖先本來就是 stop，那它不太可能致病）
conservation_file:/opt/vep/Plugins/loftee_data/loftee.sql,\\
gerp_bigwig:/opt/vep/Plugins/loftee_data/gerp_conservation_scores.homo_sapiens.GRCh38.bw \\

        --no_stats \\                             # 不產生 HTML 統計（快很多，我們也用不到）
                                                  #   ⚠️ 不能與 --stats_file 同時用

    bcftools stats ${sample_id}.vep.vcf.gz | grep "^SN" >&2
    # ★ 變異數應該與輸入完全相同（VEP 只加註解不增刪變異）。

    """

// ──────────────────────────────────────────────────────────────
// Process 2：Pangolin Splice Scoring
// ──────────────────────────────────────────────────────────────

process PANGOLIN_SCORE {
    label 'process_gpu'          // ★ 這個 label 決定 --nv 與 maxForks（見 config）

    container "${params.sif_dir}/pangolin_1.0.0.sif"

    publishDir "${params.out_dir}/${sample_id}/02_pangolin", mode: 'copy'

    input:
    tuple val(sample_id), path(vep_vcf), path(vep_tbi)

    output:
    tuple val(sample_id),
          path("${sample_id}.pangolin.vcf.gz"),
          path("${sample_id}.pangolin.vcf.gz.tbi"),
          emit: pangolin_out

    script:
    // ── GPU lock（DGX-2 共用機器）─────────────────────────────────────────
    //   與二級分析同一套機制：gpu_lock.sh 搶下 N 張空閒 V100 並輸出可 eval 的環境變數，
    //   trap EXIT 時以 gpu_unlock.sh 歸還（即使 process 失敗也會釋放）。
    //   Apptainer 預設會把 host 環境變數帶進容器，故 CUDA_VISIBLE_DEVICES 會被 Pangolin
    //   看見；這裡再明確 export 一次，避免 lock script 只設了 MY_GPUS。
    //   非 DGX（local / dgm）use_gpu_lock=false → 走 config 既有的 GPU 設定，不插入此段。
    // ── GPU / CPU 切換（--use_gpu_pangolin）──────────────────────────────
    //   Pangolin 以 PyTorch 實作，會自動偵測 CUDA；把 CUDA_VISIBLE_DEVICES 設為空字串
    //   即可強制走 CPU（慢但結果相同），讓 pipeline 能部署到沒有 GPU 的環境。
    //   容器的 --nv 由 config 的 process_gpu label 依同一參數決定是否加上。
    //   ★ 「能切 CPU」是刻意保留的能力：萬一將來要部署到沒有 GPU 的機器
    //     （或 GPU 壞掉要應急），整條 pipeline 仍然跑得動，只是慢。
    def use_gpu       = params.use_gpu_pangolin == null ? true
                        : params.use_gpu_pangolin.toString().toLowerCase() == 'true'
    //                    ↑ 又一次的字串比對（見 2.2）
    // 不用 GPU 就不必搶卡
    def use_lock      = use_gpu && (params.use_gpu_lock ?: false)
    def lock_script   = params.gpu_lock_script
    def unlock_script = params.gpu_unlock_script
    def num_gpus      = params.pangolin_num_gpus ?: 1

    // ── 三種模式，各產生一段不同的 shell 前置區塊 ──
    def gpu_block = !use_gpu ? """
    export CUDA_VISIBLE_DEVICES=""
    # ↑ 空字串 = 「看不到任何 GPU」→ PyTorch 自動退回 CPU
    echo "[PANGOLIN] ${sample_id} CPU 模式（use_gpu_pangolin=false）" >&2
    """ : use_lock ? """
    eval \$(bash ${lock_script} ${num_gpus})
    export CUDA_VISIBLE_DEVICES=\${MY_GPUS}
    # ↑ lock script 已經 export 過，這裡再一次是保險
    echo "[PANGOLIN] ${sample_id} 取得 GPU \${MY_GPUS}" >&2
    trap "bash ${unlock_script} \${MY_GPUS}; echo '[PANGOLIN] ${sample_id} 釋放 GPU \${MY_GPUS}' >&2" EXIT
    # ↑ ★ 與二級完全相同的 trap 模式：不論怎麼結束都歸還卡
    """ : """
    echo "[PANGOLIN] ${sample_id} 使用 config 指定的 GPU（未啟用 GPU lock）" >&2
    """
    """
    ${gpu_block}

    # Step 1：從 VEP 輸出中篩選 splice candidate
    # bcftools view -h → 只取 header 行
    # bcftools view -H → 只取 variant 行，awk 篩 INFO 欄含 "splice" 字眼
    #
    # 【為什麼只跑 splice candidate？】Pangolin 對每個變異要做深度學習推論，
    #   全基因體 500 萬個變異跑不完。而 Pangolin 的輸出只在「可能影響剪接」的
    #   變異上有意義。VEP 的 consequence 已經標出哪些是 splice 相關
    #   （splice_donor_variant、splice_acceptor_variant、splice_region_variant…），
    #   只跑這些就好（WGS 通常幾萬筆）。
    bcftools view -h ${vep_vcf} > splice_header.vcf
    bcftools view -H ${vep_vcf} | \\
        awk -F'\\t' '\$8 ~ /splice/' > splice_body.vcf
    #                 ↑ 第 8 欄是 INFO（含 CSQ）

    SPLICE_COUNT=\$(wc -l < splice_body.vcf)
    echo "[PANGOLIN] ${sample_id}：splice candidates = \${SPLICE_COUNT}" >&2

    if [ "\${SPLICE_COUNT}" -eq 0 ]; then
        # 無 splice candidate，產生空輸出
        #   ★ 必須產生「只有 header 的合法 VCF」而不是空檔或不產生 ——
        #     下游 parse_vep_csq.py 一定會去讀這個檔，缺檔會讓整個 task 失敗。
        echo "[PANGOLIN] 無 splice candidate，產生空輸出" >&2
        bgzip -c splice_header.vcf > ${sample_id}.pangolin.vcf.gz

    else
        # ★★ Step 2：兩個 Pangolin segfault 的 workaround ★★
        # Step 2：移除 CSQ + 過濾 alt/random contig，再送 Pangolin
        # 原因 1：WGS CSQ 可能長達 270KB，Pangolin parse 時 segfault
        #         【為什麼 CSQ 會這麼長？】一個變異若落在多個重疊基因上，
        #         VEP 會為每個轉錄本產生一組註解。加上 dbNSFP 的十幾個分數欄位，
        #         單一變異的 CSQ 可以到數百 KB。Pangolin 的 VCF parser 有固定
        #         緩衝區大小，超過就 segfault（而且不會給錯誤訊息）。
        # 原因 2：Pangolin gencode DB 沒有 alt/random contig 的 gene model，
        #         碰到 chr*_alt / chr*_random / chrUn_* 也會 segfault
        # bcftools view --regions 需要 bgzip+tabix 輸入，無法直接接 pipe
        # 改用 grep + awk：先移除 CSQ，再只保留標準染色體（chr1-22,X,Y,M）
        # alt/random contig 的 Pangolin gencode DB 沒有 gene model，會 segfault
        cat splice_header.vcf splice_body.vcf \
            | bcftools annotate -x INFO/CSQ \        # 移除 CSQ（Pangolin 不需要）
            | grep -E '^#|^chr([0-9]+|[XYM])\t' \    # 只留標準染色體
            > splice_for_pangolin.vcf
        #   ★ CSQ 被移除不影響結果：Pangolin 的輸出會另存一份 VCF，
        #     下游 parse_vep_csq.py 用「座標」把兩份 join 回來。

        # Step 3：執行 Pangolin（GPU）
        # output_file 是 prefix，Pangolin 自動加 .vcf
        # 不要給 ${sample_id}.pangolin.vcf，否則輸出變成 .vcf.vcf
        #   ★ 這種「參數是 prefix 還是完整檔名」的差異很容易踩，
        #     踩到的話下游會找不到檔案（而且錯誤訊息只會說「檔案不存在」）。
        # IUPAC ambiguity code（Y/R/W 等）已在 sif build 時 patch 處理，
        # 碰到非 ACGT 字元一律當 N（全零 encoding），不會 crash
        #   ★ 第三個 Pangolin 的坑：hg38 參考序列裡有極少數 IUPAC 模糊碼，
        #     Pangolin 原始碼的 one-hot encoding 只處理 ACGTN，
        #     遇到 Y/R/W 會 KeyError。已在建容器時 patch 掉。
        pangolin \\
            splice_for_pangolin.vcf \\
            ${params.ref_fasta} \\
            ${params.pangolin_db} \\               # gencode v47 gene model DB
            ${sample_id}.pangolin \\               # ← prefix，不含 .vcf
            --distance 50 \\                       # 搜尋範圍 ±50 bp
                                                   #   （剪接位點的影響範圍；
                                                   #    調大會慢很多但抓得到遠端效應）
            -m True                                # 輸出每個位點的最大分數（mask 模式）

        bgzip -c ${sample_id}.pangolin.vcf > ${sample_id}.pangolin.vcf.gz
    fi

    tabix -p vcf ${sample_id}.pangolin.vcf.gz
    echo "[PANGOLIN] ${sample_id} 完成" >&2
    """
}
```

## 4.7 dbNSFP 兩個版本的差異總表

| 項目 | 4.9c（預設） | 5.3a（`--academic_dbnsfp`） |
|------|------------|---------------------------|
| 授權 | 內含工具皆可商用 | 含 CADD/REVEL 等，**商用需另行授權** |
| ACMG 族群頻率 | `gnomAD_exomes_AF` / `_EAS_AF`（2.1.1，~125k） | `gnomAD2.1.1_exomes_non_cancer_AF` / `_EAS_AF`（~118k） |
| **ACMG 行為** | — | **相同**（刻意讓 PM2/BA1/BS1 不因換版而變） |
| 共同的 in-silico | BayesDel、AlphaMissense、ESM1b、VARITY、SIFT、DANN、PHACTboost、phyloP、GERP++ | 同左 |
| 額外的 in-silico | — | REVEL、MutPred2、VEST4、CADD_phred（**參考用，不計分**） |
| 額外的頻率 | — | gnomAD 4.1 joint AF / EAS_AF（**參考用，不計分**） |
| P-KNN | 已 merge | 已 merge（覆蓋更完整） |
| 版本記錄 | TSV 的 `DBNSFP_VERSION` 欄 | 同左 |

**為什麼 5.3a 只有 `non_cancer` 子集？** dbNSFP 5.3a 移除了 gnomAD 2.1.1 的
「整體」欄位，只保留三個子集：`controls`（~60k）、`non_neuro`、`non_cancer`（~118k）。
選 `non_cancer` 是因為它的樣本數最接近原本的整體（~125k）；
`controls` 只有一半，換過去會讓 PM2 的判定明顯偏移。

## 4.8 in-silico 預測分數涵蓋率的說明（評鑑常問）

實測：81 欄 TSV 中，有 in-silico 分數的變異約占 **1/4**。

**這是預期的，不是 bug**。原因：

1. **dbNSFP 只收 nsSNV**（非同義單核苷酸變異）——
   涵蓋 missense、nonsense、剪接位點，**不含** indel、同義變異、內含子變異。
   而一份 WGS/WES 的變異中，這三類佔絕大多數。
2. 針對「真正應該有分數的母體」來看，涵蓋率很高：
   - **missense 變異中 94.3% 有 REVEL**
   - **missense SNV 母體中 95.9% 有分數**
3. 剩下沒對到的，經逐一檢查主要是 **PRAMEF 家族的旁系同源基因**
   （高度重複的基因家族，dbNSFP 的轉錄本對應本來就不完整）。

另外，**P-KNN 的 missense 涵蓋率比 dbNSFP 低約 1.78%**，原因是
P-KNN 建置時**只取每個基因的 MANE Select 轉錄本**，
非 MANE 轉錄本上的變異自然沒有分數。（已用 orphan 統計確認：
P-KNN 中的每一筆幾乎都有對應到 dbNSFP，orphan ≈ 0。）
